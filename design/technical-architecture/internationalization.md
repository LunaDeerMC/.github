# 国际化与双语路由

> 返回[技术架构入口](./README.md)。

- 最后更新：2026-07-23
- 状态：语言范围、URL、内容组织、翻译完整性、搜索与首次访问行为已确认

## 总体结论

网站全局支持中文与英文：

```ts
type Locale = "zh-CN" | "en";
```

中文是默认语言，不增加 URL 前缀；英文统一使用 `/en` 前缀：

```text
中文                              英文
/                                 /en/
/works                            /en/works
/works/{work}                     /en/works/{work}
/docs/{...path}                   /en/docs/{...path}
/support                          /en/support
/about                            /en/about
/search                           /en/search
```

现有中文信息架构和公开路径保持不变。英文页面拥有独立静态 URL，不通过客户端运行时把中文页面替换成英文内容。

## URL 是语言事实源

- 当前 URL 决定页面语言。
- 无前缀路径始终表示中文，`/en` 前缀始终表示英文。
- 用户直接打开或收到分享的 URL 时，不因 `localStorage`、浏览器语言或上一次选择而被强制改写。
- 不使用客户端 JavaScript 在首屏绘制后自动跳转语言，避免闪烁、历史记录污染和不可预测分享行为。
- 不使用 `localStorage` 等长期存储记忆语言选择；用户通过语言切换进入的新 URL 就是后续浏览的语言上下文。
- 站内链接默认延续当前 URL 的 locale，不能依赖长期偏好猜测目标语言。
- 页面根元素必须输出正确的 `lang="zh-CN"` 或 `lang="en"`。

## 首次访问语言建议

网站不自动重定向语言，只允许在一个非常收敛的场景中提供非阻断提示：

- 仅当用户直接进入中文首页 `/`，且浏览器首选语言不属于中文时，提示存在英文版本。
- 提示文案保持轻量，例如 `English version available.`，只提供“查看英文版”和关闭两个操作。
- 提示不能覆盖首屏主体、阻止滚动或抢占键盘焦点，也不能改变当前 URL。
- 用户选择英文后正常进入 `/en/`；关闭后继续停留在中文首页。
- 使用 `sessionStorage` 记录当前会话已展示或已关闭，避免同一会话重复出现。
- 深层链接、作品页、文档页、支持页和关于页不显示该提示，避免干扰从搜索或分享链接进入的用户。
- 该会话标记不是语言偏好，不跨会话、跨设备或长期保存。

## 对应页面

内容领域层不能通过简单添加或删除 `/en` 字符串猜测页面对应关系。每个可翻译页面需要稳定的语言无关标识，例如：

```ts
interface LocalizedRoute {
  routeId: string;
  locale: Locale;
  pathname: string;
}
```

- `routeId` 表示同一语义页面，`pathname` 表示该语言的公开 URL。
- 语言切换根据 `routeId` 查找目标语言版本。
- 作品只有一份内容目录和一个入口文件，slug 与作品标识天然跨语言共用。
- 文档集标识由 locale 目录上方的物理路径确定；文档页面是否为对应翻译，按去掉 locale 层后的相对路径识别。
- 非文档页面必须存在目标语言版本。
- 文档页面缺少目标语言版本时不寻找最近祖先、不回退到中文正文，也不静默跳回首页；目标 URL 直接进入对应语言的 404 页面。

## 静态生成

- 中文与英文页面都在构建时生成完整 HTML。
- Astro 路由层根据标准化的本地化路由清单生成页面，不在浏览器运行时翻译正文。
- 固定官网页面、作品页、文档页、搜索页和 404 都需要获得明确 locale。
- 公共布局、导航、页脚、搜索界面和组件文案从类型安全的本地化消息源读取。
- 不能在 Astro、React Island 和 MDX 组件中分别维护互不一致的硬编码翻译。

## 翻译完整性

除文档页面外，所有公开静态页面都必须同时具有中文和英文版本，包括：

- 首页、支持、关于、搜索和 404。
- 作品列表、分类、归档列表和所有作品介绍页。
- 默认 `index.mdx` 作品页与自定义 `index.astro` 作品页。
- 文档首页与文档分类页等固定官网页面。
- 导航、页脚、搜索、提示、错误状态和组件界面文案。
- 页面标题、描述、图片替代文本和其他当前语言所需的 SEO 元数据。

以上任一内容缺少中文或英文时构建失败。

只有 `docs/` 内容源中的具体文档页面和文档集允许单独存在中文或英文：

- 缺少另一语言时构建只警告，不阻止已有语言发布。
- 不生成不存在语言的静态页面、搜索记录、侧边栏条目或站点地图 URL。
- 只有真实存在精确对应翻译时才输出另一语言的 `hreflang`。
- 不使用运行时机器翻译、混合语言外壳或占位正文补齐缺失版本。
- 每种语言的文档侧边栏与上一篇/下一篇都只根据该语言真实存在的文档生成。

固定页面链接到某份可选文档时，当前语言的目标文档必须真实存在，否则该链接不能输出；内部链接校验仍将不存在的目标视为错误。

## 双语内容源组织

### 固定官网页面

固定官网页面按页面拆分文案，不按语言建立两棵目录。同一页面的中文与英文文案放在同一个 TypeScript 文件中，便于逐项翻译和对照：

```text
src/i18n/
├── common.ts
├── home.ts
├── support.ts
├── about.ts
├── search.ts
└── errors.ts
```

- `common.ts` 保存导航、页脚和通用操作等跨页面界面文案。
- 每个页面文件同时包含 `zh-CN` 和 `en`，并通过共享类型保证字段结构一致。
- 页面布局、组件和视觉实现仍使用一份 Astro 源码；中文与英文静态路由向同一页面实现传入不同 locale。
- 缺少任一语言字段时构建失败。

### 作品

作品继续保留原有单目录与单入口结构，不增加 `zh-CN/` 和 `en/` 页面目录：

```text
src/content/works/{work}/
├── data.yaml
├── index.mdx | index.astro
├── copy.ts
├── components/
├── styles/
└── assets/
```

- 使用 `index.mdx` 时，在同一个 MDX 文件中通过构建期语言标签标记中文和英文正文；最终静态页面只输出当前 locale 的内容。
- MDX Frontmatter 与 `data.yaml` 中需要翻译的结构化字段使用明确的本地化值，不能复制成两份入口文件。
- 使用自定义 `index.astro` 时，布局与特效继续只维护一份；可见文案放入同目录的 `copy.ts`，该文件同时保存中文和英文。
- `copy.ts` 只在自定义页面需要结构化翻译文案时存在，不要求默认 MDX 作品创建空文件。
- 不能通过 CSS 或客户端 JavaScript 把两种语言同时输出后再隐藏其中一种；语言选择必须在构建渲染阶段完成。

默认作品 MDX 使用以下构建期语言标签：

```mdx
<Localized locale="zh-CN">

## 中文介绍

这里是中文正文。

</Localized>

<Localized locale="en">

## English introduction

English content goes here.

</Localized>
```

- 每个 `index.mdx` 必须且只能包含一个 `zh-CN` 和一个 `en` 顶层 `Localized` 块。
- 两个语言块都必须包含有效正文，否则构建失败。
- `Localized` 不能互相嵌套。
- 可见正文必须位于语言块中；MDX import、变量定义、导出、注释和空白可以位于块外。
- 两种语言的正文都禁止一级标题；唯一一级标题继续由默认作品布局生成。
- 构建中文页面时只渲染中文块，构建英文页面时只渲染英文块。
- `Localized` 是构建期 MDX 组件，不进行客户端 Hydration。

结构化内容采用字段优先、翻译并排的本地化叶子值：

```ts
type LocalizedText = {
  "zh-CN": string;
  en: string;
};
```

```yaml
summary:
  zh-CN: 用于作品列表、搜索和 SEO 的一句说明
  en: A concise description for listings, search, and SEO
```

- URL、ID、枚举、日期、GitHub 地址、图标引用和其他语言无关字段只保存一次。
- 需要翻译的文本叶子使用 `LocalizedText`，不复制整份 `data.yaml` 或 Frontmatter。
- 作品页面要求中英双语，因此本地化叶子缺少任一语言时构建失败。
- `data.yaml` 的精确字段划分以[作品索引数据](./work-index-data.md)为准；默认 `index.mdx` Frontmatter 的精确字段划分以[默认作品页 Frontmatter](./default-work-page-frontmatter.md)为准。

自定义 Astro 页的 `copy.ts` 使用相同的字段优先结构：

```ts
export default defineLocalizedCopy({
  hero: {
    title: {
      "zh-CN": "可靠而简单的权限管理",
      en: "Reliable and simple permission management",
    },
  },
});
```

共享解析函数在构建渲染前把文案树转换成当前 locale 的普通对象，页面组件不需要在每个文本位置重复书写 `[locale]`。

### 文档

文档是唯一按语言建立独立内容树的内容类型。语言目录放在每个文档集内部：

```text
docs/plugins/example-work/
├── zh-CN/
│   ├── index.mdx
│   ├── installation.mdx
│   └── configuration/
│       └── index.mdx
├── en/
│   ├── index.mdx
│   └── installation.mdx
└── assets/
```

- `docs/plugins/example-work/` 仍是同一个文档集，locale 目录不进入文档集 ID。
- 每种语言的侧边栏从自己的真实目录生成，允许页面数量和内部结构不同。
- 文档集共享素材放在文档集根目录，语言专属素材可以放在对应 locale 目录。
- 构建生成 URL 时去掉内容源中的 locale 目录，再按规则为英文增加 `/en` 前缀。
- 文档集至少需要存在一种语言的根 `index.md` 或 `index.mdx`。
- 文档文件只包含当前语言，`title`、`description` 与 `sidebar.label` 不使用双语对象。
- 去掉 locale 目录后的物理相对路径相同时，识别为对应翻译。
- `link` 与正文站内链接使用不含 `/en` 的语言无关路径；英文构建自动增加 `/en`。
- 两种翻译可以通过各自 `link` 使用不同 slug，但翻译关系仍由源文件相对路径确定。
- 两种语言都存在时，文档集根页面的 `documentSet.order`、`documentSet.status` 和 `icon` 必须一致；其他页面顺序、隐藏、草稿和布局可以独立。

## SEO 与站点输出

- 每个公开页面输出指向自身语言 URL 的 canonical。
- 存在对应翻译时输出中文与英文 `hreflang` 关系。
- `x-default` 的最终策略在部署与 SEO 细节阶段确认；不得创建重复 canonical 页面伪装成语言版本。
- 站点地图包含所有公开中文和英文页面，并保留明确语言对应关系。
- Open Graph、页面标题、描述、结构化数据和图片替代文本都使用当前页面语言。
- Pagefind 根据最终 HTML 的 `lang` 在一次构建后处理中自动生成和加载对应语言索引；中文与英文结果严格隔离，不进行跨语言索引合并。

## 导航语言切换

- 语言切换位于全站导航功能菜单，在所有全站双主题页面中始终可用。
- 选项使用 `中文` 与 `English` 自称，不使用国旗表示语言。
- 切换时优先进入当前 `routeId` 的另一语言版本。
- 非文档页面必定存在另一语言版本。
- 文档缺少对应翻译时，切换后进入目标语言对应路径并由该语言 404 页面处理，不回退到文档集首页或分类页。
- 当前选中语言从 URL 读取；切换语言只负责导航到目标 URL，不写入长期语言偏好。
- 语言切换不会修改主题偏好，主题切换也不会修改语言。
- 自定义作品页仍需提供全局语言切换能力，或以同等清晰的方式进入对应语言版本。

## 错误处理与校验

构建期至少需要校验：

- locale 只允许 `zh-CN | en`。
- 中文路由不能错误包含 `/zh` 前缀。
- 英文公开路由必须位于 `/en` 下。
- 同一 locale 内 pathname 唯一。
- 同一 `routeId + locale` 最多存在一个页面。
- 页面 canonical、`hreflang` 与实际生成路由一致。
- 组件和内容元数据不能缺少当前语言所需的核心界面文案。
- 非文档公开页面缺少任一语言版本时构建失败。
- 文档缺少对应语言时只警告；不存在的翻译不能进入对应语言的导航、搜索、站点地图或 `hreflang`。
- 文档源 `link` 和普通站内链接显式包含 `/en` 时构建失败；英文前缀统一由路由解析器添加。
- 当前语言正文主动链接到不存在的当前语言页面时构建失败，不使用 404 掩盖已知坏链接。
- Pagefind 构建后必须验证中文索引不包含 `/en/**`，英文索引不包含无前缀中文页面。

## 已确认的技术结论

React 是 LunaDeerMC 官网唯一的客户端 UI 框架，采用 Astro Islands 方式按需使用；不将全站改造成全量 Hydration 的 React SPA，也不同时引入 Vue、Preact、Svelte 等第二套客户端组件运行时。

职责边界如下：

```text
Astro
├── 页面路由与布局
├── 静态 HTML、SEO 与无 JavaScript 基础内容
├── 官网、默认作品页和文档主体
└── 决定每个 Island 的加载时机

React Islands
├── 需要浏览器状态的复杂交互
├── 页面加载后的异步数据
├── 沉浸式视觉与交互组件
├── 可选 Canvas、WebGL 与 3D 场景
└── 作品专属的高级体验组件
```

- `.astro` 是固定官网页面、布局和自定义作品主页的入口格式。
- `.tsx` 用于由 Astro 显式导入的客户端交互或视觉组件，不直接成为作品或文档内容入口。
- React 组件只消费内容领域层已经聚合和校验的数据，不扫描内容目录，也不承担路由生成。
- 静态正文和关键操作在 React 加载失败或 JavaScript 被禁用时仍应可见、可理解；确实依赖网络或浏览器能力的增强功能提供清晰降级。

## 已确认的体验目标

整站都需要具有惊艳、沉浸且高级的品牌体验，不把表现力只留给特殊作品主页。首页“轻量”指内容数量和信息密度较低，不表示视觉表现需要保守。

全站采用分级体验强度：

- **品牌模式**：首页、作品列表、支持中心和关于我们可以使用更强的构图、动态背景、转场、滚动叙事和局部互动。
- **阅读模式**：文档延续品牌颜色、材质和空间语言，但降低持续运动，让排版、留白与信息层次成为主要质感来源。
- **作品模式**：默认作品页保持信息清晰并提供精致互动；自定义作品主页可以进一步使用作品专属动效、Canvas、WebGL 或 3D。

沉浸式体验不能破坏内容、性能和无障碍底线。关键内容不等待动画结束后才出现；所有动态能力支持 `prefers-reduced-motion`，并为低性能设备、触摸设备和不支持相关浏览器能力的环境提供降级。

首页已确认四层 Minecraft 单一场景、远慢近快视差和同色过渡，完整设计边界见[首页视觉方向](../homepage-visual-direction.md)。隔离原型曾使用 CSS 透视空间与 `8 / 5 / 2 / 1` 深度层级验证概念；其速度体感、素材和参数均未通过验收。导航、Hero 文案与按钮保持真实 DOM。

当前正式实现位于 `src/components/home/HomeHero.astro` 与 `src/styles/global.css`：Hero 使用一个延展滚动区和 sticky 视口，背景、远景、中景、近景四层分别向上移动。白天与黑夜各自拥有一套重新设计的场景母版与四层资源；四层颜色像素统一来自对应母版，远景、中景、近景保留独立 alpha 轮廓，天空层使用完整母版作为无缝底板，因此初始画面不会出现天空露底、湖面断裂或建筑错位。站点配置仍逐层引用，不从旧合成图做切片，也不依赖 CSS 假遮罩。当前桌面位移基线为 `-10 / -42 / -88 / -156px`，移动端为 `-8 / -28 / -58 / -112px`；这些参数只控制滚动幅度，不改变四层的空间顺序。

首页滚动时由 CSS 透视空间自动产生差速视差，Hero 内容使用轻量透明度与纵向位移退场；精确设计与减少动态边界以[全站动效与首页视差系统](../motion-system.md)为准。

### 首页精选作品的运行时展示

首页精选作品遵守“构建完整候选、展示时随机抽样”的边界：

- 内容领域层在构建时提供全部 `featured: true` 标准化作品记录，不预先随机截断。
- Astro 输出可访问的静态回退和完整候选数据；浏览器在每次页面加载时随机选择最多三件并随机排列。
- 候选为空时构建阶段完整省略该区块，不加载不必要的客户端增强代码。
- 同一页面生命周期内只抽样一次；滚动、窗口变化和主题切换不能重新抽样或造成作品跳动。
- 中文与英文是独立静态页面，完整语言导航可以在目标页面重新抽样。
- JavaScript 失败或被禁用时保留稳定、可理解且最多三件的静态回退。

随机抽样可以实现为最小 React Island 或页面级脚本，但必须消费领域层已经标准化的数据，不自行扫描内容目录。实现应避免 Hydration 不一致、可见内容闪换和布局位移；视觉回归与端到端测试通过注入固定随机源获得可重复结果。

主题职责已经确认并由[全站主题策略](../theme-strategy.md)维护：包括首页、支持和关于在内的所有通用页面支持浅色与深色；自定义 `index.astro` 作品页自行决定主题。首页深色使用“黄昏红石工坊”，浅色使用“白天牧场”，并切换完整四层资产组。主题偏好使用 `system | light | dark` 三态并通过 `localStorage` 持久化；`system` 根据 `prefers-color-scheme` 推导实际主题。主题切换控件的具体视觉形态仍待决定。

## 待继续决定

以下技术不因“整站沉浸”目标而自动采用。必须先完成视觉方向探索和代表页面视觉稿，再根据选定设计中真实存在的交互、转场和媒体需求进行选择：

- 哪些全站组件使用 React Island，哪些简单行为保留为 Astro 页面脚本或纯 CSS。
- 各 Island 使用 `client:load`、`client:idle`、`client:visible` 或其他策略的具体规则。
- 是否在全站启用 Astro ClientRouter，以及跨页面持久体验层和脚本生命周期规则。
- 选择 GSAP、Motion 或组合方案作为主要动画工具的边界。
- 是否引入 React Three Fiber，以及 3D、Shader 和 Canvas 的性能预算与降级条件。
- 全局交互状态、跨 Island 通信和页面导航后的状态恢复方式。

决策顺序固定为：

```text
视觉方向与品牌母题
        ↓
首页及代表页面视觉稿
        ↓
动效与页面连续性设计
        ↓
技术能力清单与性能预算
        ↓
ClientRouter、动画库、3D 与 Hydration 选型
```

在完成前三步以前，ClientRouter、持久化全局体验层、GSAP、Motion 和 React Three Fiber 都只是候选方案，不写成项目依赖或强制架构。

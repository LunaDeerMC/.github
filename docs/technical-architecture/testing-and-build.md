## 测试体系

使用 `astro check`、Vitest、项目专用生产构建验证器、Playwright 和 `@axe-core/playwright` 组成分层测试体系。不同工具各自覆盖明确职责，不同时引入 Jest、Cypress 等职责重叠的测试框架。

- `astro check`：执行 Astro 模板和 TypeScript 静态诊断，作为 CI 的第一道检查。
- Vitest：测试内容领域层的纯 TypeScript 逻辑，包括作品聚合、文档集边界、侧边栏、页面前后关系、永久链接、图标引用和跨内容校验。
- 项目专用生产构建验证器：在 Astro 与 Pagefind 完成构建后核对最终静态产物，不开发通用链接检查工具。
- Playwright：针对包含 Pagefind 索引的完整生产预览执行页面流程、交互、响应式布局和搜索测试。
- `@axe-core/playwright`：在代表页面与展开后的交互状态上执行自动化可访问性检查，并辅以键盘操作测试。
- Playwright 截图比较：只覆盖少量关键页面和固定视口，不为所有页面建立高维护成本的视觉快照。

## Vitest 覆盖范围

- `data.yaml` 与 `index.mdx` 或 `index.astro` 的作品聚合。
- 作品入口冲突、缺失入口与缺失数据。
- 默认作品页 Frontmatter Schema、获取档次和访问模式一致性。
- 默认 `index.mdx` 的完整内容校验与自定义 `index.astro` 的共有校验边界。
- `data.yaml` 与 `index.mdx` 未知字段的 Warning，以及已知字段缺失或无效时的 Error。
- Minecraft 版本与平台兼容性列表的空值、去空白、重复项警告和顺序保留。
- 结构化文本的去空白、空值、单行纯文本和不限制字符数规则。
- 获取档次 ID、推荐项、标准链接与渠道的硬冲突，以及 benefits、other 链接和普通 URL 重复的警告与去重。
- GitHub 仓库地址标准化，以及客户端 Releases 适配器对成功、空列表、预发布、限流和网络错误响应的处理。
- 文档集根目录识别和侧边栏隔离。
- 排序、隐藏以及上一篇和下一篇边界。
- 永久链接推导与重复链接检测。
- `lucide:*` 与 `local:*` 图标验证。
- 草稿和归档内容处理。
- Pagefind 元数据生成和 `loadSiteConfig()` 校验。
- 首页精选候选提取、零候选省略、一至三件全量展示、超过三件抽样上限，以及注入固定随机源后的可重复选择。

测试数据使用独立 fixture，不把真实官网内容作为领域规则的唯一测试输入：

```text
tests/
├── fixtures/
├── unit/
├── build/
├── e2e/
└── visual/
```

## 生产构建验证器

生产构建验证器检查：

- 内容路由与最终 HTML 一致。
- 站内链接、标题锚点、本地图片、SVG 和下载资源有效；远程封面与图库图片只检查 HTTPS URL 格式，不检查实时可访问性。
- 草稿内容没有进入生产构建。
- Pagefind 索引、站点地图和 404 页面存在且有效。
- 默认作品页的静态可选标签页与本地内容一致；“版本与更新”只生成客户端加载入口，不在构建期判断远程 Release 是否为空。
- 公开页面没有暴露付费作品的受保护文件链接。
- 站内 URL 指向有效路由，外部 URL 使用 HTTPS；普通构建不依赖第三方地址实时可访问。
- 自定义作品主页成功生成最终 HTML，并包含有效页面标题、摘要和主内容区域；不检查默认模板专属的标签页或结构化获取字段。

## 端到端测试

Playwright 覆盖：

- 全站导航。
- 作品列表、默认作品介绍页和自定义作品主页的主要路径。
- 默认作品页的介绍、图库、版本与更新、获取方式标签页。
- 使用网络拦截模拟 GitHub Releases 的成功、空列表、限流和网络失败，不让测试依赖 GitHub 的实时可用性。
- “查看文档”入口和外部获取链接。
- 文档桌面导航、移动端工具栏和目录抽屉。
- 搜索弹窗、完整搜索页、中文与 Minecraft 技术词搜索。
- 键盘操作和关键可访问性状态。
- 首页精选作品只来自 `featured` 候选、最多显示三件、当前页面内主题切换不重新抽样，并在禁用 JavaScript 时保留静态回退。

普通提交可以只运行 Chromium；主分支或发布检查运行 Chromium、Firefox 和 WebKit。

## 视觉回归

视觉回归只为以下代表页面保留基线：

- 首页。
- 作品列表。
- 默认作品介绍页。
- 一张代表性自定义作品主页。
- 文档阅读页。
- 搜索结果页。

使用固定的桌面端与移动端视口，在统一 CI 环境中以 Chromium 运行。动态内容在测试中固定或隐藏；首页精选作品通过固定随机源选择同一组候选，不能依赖真实随机结果建立视觉基线。

## Astro 组件测试边界

Astro Container API 目前不是首期核心测试依赖。组件逻辑优先提取为纯函数交给 Vitest，真实渲染交给 Playwright；只有确实适合字符串渲染验证的少量组件才考虑使用 Container API。

## 构建顺序

```text
内容 Schema 与跨内容校验
        ↓
astro check
        ↓
Vitest
        ↓
Astro 静态构建
        ↓
Pagefind 索引
        ↓
生产构建验证器
        ↓
Playwright 与 axe
```

GitHub Releases 不属于构建输入。生产构建只校验仓库 URL 的结构，不访问 GitHub；Release 数据在浏览器加载页面后获取，运行时失败不能影响官网发布或页面其余内容。`data.yaml` 与 `index.mdx` 的未知字段只警告，必填字段、已知字段类型、链接、资源和路由错误仍应阻止构建。

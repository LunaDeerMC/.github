## 这套文档服务谁

这套文档面向需要下载、部署和维护 DeerFolia 的服务器服主、运维人员和普通服务器消费者。文档会先说明“能不能用”和“怎么安全启动”，再解释性能配置，不要求读者先了解 Java 源码或 Paperweight 补丁开发。

DeerFolia 是服务端核心，不是插件。你需要把它作为启动命令中的服务器 jar 使用；不要把它放进 plugins 目录，也不要在 Paper 或 Purpur 进程里加载 DeerFolia 配置。

- DeerFolia：仓库 tag 26.2.0-bbeb1d1。
- Minecraft：26.2。
- Java：25。
- 上游：PaperMC Folia，具体提交由仓库 gradle.properties 中的 foliaRef 固定。

发行版和源码可能继续更新。如果下载页的 tag、日志或自动生成配置与本文不同，应优先使用当前构建实际生成的文件，并将差异反馈到 [DeerFolia Issues](https://github.com/LunaDeerMC/DeerFolia/issues)。

## 开始前的安全边界

切换服务端核心前，至少备份以下内容：

- 所有世界目录；
- server.properties、eula.txt、配置目录；
- 插件数据、数据库和定时任务；
- 当前正在使用的服务端 jar 与启动脚本。

第一次启动建议使用复制出来的测试服务器。确认插件加载、玩家登录、传送、区块加载和常用机器都正常后，再迁移生产服务器。

## 先判断是否适合

Folia 的优势来自把相互分离的玩家区域并行运行。服务器玩家长期集中在同一片区域时，换用 Folia 衍生核心不一定更快；同时，很多传统 Paper 插件无法直接在 Folia 上工作。请先看插件作者是否明确提供 Folia 支持，再决定迁移。

DeerFolia 的自定义优化也可能改变高密度实体、村民 POI、路径查找和挂机玩家的数据同步节奏。默认值适合先启动和观察，不代表每种服务器拓扑都应保持不变。

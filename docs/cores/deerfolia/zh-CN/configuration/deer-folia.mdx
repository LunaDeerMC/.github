## 默认文件

以下是当前源码生成的主要结构。启动后文件会带有同等含义的注释；如果你的版本新增或减少了字段，以实际生成文件为准。

~~~yaml
dynamic-activation-brain:
  enabled: true
  start-distance: 12
  activation-distance-mod: 8
  maximum-activation-prio: 20

async-pathfinding:
  enabled: true
  async-pathfinding-keep-alive: 60
  async-pathfinding-max-threads: 20

kaiiju-entity-throttling: true

network-optimizations:
  optimized-var-int: true
  optimized-frame-encoding: true

lithium-optimize:
  enabled: true
  allocations: true
  ai: true
  collections: true
  entity: true
  math: true
  world: true

poi-optimizations:
  enabled: true
  golem-spawn-check-interval: 200
  secondary-poi-sensor-interval: 80
  village-distance-cache-duration: 100
  golem-spawn-player-distance-limit: 128

afk-network-optimization:
  enabled: true
  afk-threshold-ticks: 1200
  afk-enter-message: "&7[AFKNet] &eYou are now AFK. &7DeerFolia will temporarily suppress non-essential packets to save bandwidth."
  afk-exit-message: "&7[AFKNet] &aWelcome back! &7During this AFK session, you saved &b{saved_traffic} &7of traffic and up to &b{saved_bandwidth} &7of bandwidth. &aThanks for helping the server save costs!"
  count-look-changes-as-activity: true
  resync-on-resume: true
  stats-enabled: true
  suppression-whitelist-categories: []
  max-suppressed-bytes-before-category-resync: -1
~~~

## Dynamic Activation of Brain

这一组配置让远离玩家的实体降低 AI 激活频率，减少没有玩家观察时的实体计算。

| 键 | 默认值 | 说明 |
| --- | ---: | --- |
| enabled | true | 总开关。关闭后恢复较接近上游默认的实体激活节奏。 |
| start-distance | 12 | 开始降低激活频率的距离。 |
| activation-distance-mod | 8 | 距离衰减参数。数值越小，远处实体通常越早或越明显地降低计算频率。 |
| maximum-activation-prio | 20 | 最大间隔上限，20 表示实体即使很远也至少按约每 20 tick 计算一次。 |

如果刷怪塔、村民交易区或红石装置的行为出现明显延迟，可以先把 activation-distance-mod 调小，或把 start-distance 调大。每次只改一个值，并在实体密集区域测试。

## Async Pathfinding

这一组配置把部分路径查找放到异步任务中，减少实体路径查找阻塞当前区域 tick 的机会。

| 键 | 默认值 | 说明 |
| --- | ---: | --- |
| enabled | true | 异步路径查找总开关。 |
| async-pathfinding-keep-alive | 60 | 单个路径线程的最大活跃时间，单位为 tick。 |
| async-pathfinding-max-threads | 20 | 异步路径线程池大小。项目实现使用虚拟线程，不等同于物理核心数。 |

README 给出的经验范围是 10–20。过小可能让路径任务排队，过大通常不会立即产生明显收益，但会增加调度与垃圾回收压力。遇到实体寻路异常或 CPU、GC 波动时，先降低线程数；相关配置修改后必须重启。

## Kaiiju Entity Throttling

kaiiju-entity-throttling 是总开关，详细规则在[实体节流配置](./entity-throttling)。关闭后，DeerFolia 不会使用 kaiiju-entity-throttling.yml 中的限制。文件可以保留，之后重新开启时会继续使用，但不要在没有验证的情况下给所有实体添加很低的 limit。

## Network Optimizations

这一组没有单独的 enabled 总开关：

| 键 | 默认值 | 作用 |
| --- | ---: | --- |
| optimized-var-int | true | 优化网络包长度字段的 VarInt 读写。 |
| optimized-frame-encoding | true | 优化网络帧编码路径，减少准备出站数据时的开销。 |

它们影响网络包处理的内部路径，不会改变玩家可见功能。遇到代理、压缩插件或网络协议相关问题时，可以在测试副本中逐项关闭，以判断是否与优化路径有关。

## Lithium Optimize

这一组移植了部分 Lithium 服务端热路径优化，并按 Folia 的区域线程模型做了适配。enabled 是总开关，其他键控制优化类别：

| 键 | 主要作用 |
| --- | --- |
| allocations | 减少高频路径中的临时对象分配。 |
| ai | 优化实体 AI 行为遍历。 |
| collections | 在实体属性等路径使用更轻量的集合访问方式。 |
| entity | 跳过不必要的实体工作和仅客户端需要的粒子逻辑。 |
| math | 使用更容易被 JVM 优化的数学热路径。 |
| world | 优化世界生成、天气和冻结检查等路径。 |

这些选项都要求服务器重启。它们不是完整的 Lithium 功能集合，也不替代 Paper、Folia 或 Moonrise 已经提供的优化。遇到实体、红石或天气行为异常时，先在测试服关闭 enabled，而不是同时修改多个子项。

## POI Optimizations

这一组面向村民的 Point of Interest 检查。数值单位都是 tick 或方块距离：

| 键 | 默认值 | 说明 |
| --- | ---: | --- |
| enabled | true | POI 优化总开关。 |
| golem-spawn-check-interval | 200 | 每名村民进行铁傀儡生成检查的最小间隔，约 10 秒。 |
| secondary-poi-sensor-interval | 80 | 次级 POI 传感器扫描的最小间隔，约 4 秒。 |
| village-distance-cache-duration | 100 | 村庄距离计算缓存时间，约 5 秒。 |
| golem-spawn-player-distance-limit | 128 | 玩家距离超过该值时，跳过部分铁傀儡生成检查。 |

大规模村民区可以从默认值开始观察 CPU。若铁傀儡农场或职业站点对时序非常敏感，先降低检查间隔，或暂时关闭 enabled 验证差异。

## AFK Network Optimization

启用后，玩家连续一段时间没有活动时，核心会抑制部分非必要的客户端数据包；玩家恢复活动后，核心会补做必要同步。它主要节省挂机场景的带宽，不应被理解为让挂机玩家停止世界逻辑。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| enabled | true | AFK 网络抑制总开关。 |
| afk-threshold-ticks | 1200 | 连续 1200 tick 无活动后进入 AFK，约 60 秒。 |
| count-look-changes-as-activity | true | 只转动视角是否算恢复活动。 |
| resync-on-resume | true | 恢复活动时补发附近区块和实体同步，建议保持开启。 |
| stats-enabled | true | 是否累计 /afknetstats 使用的统计数据。 |
| suppression-whitelist-categories | [] | AFK 时仍然放行的类别列表。 |
| max-suppressed-bytes-before-category-resync | -1 | 单玩家、单类别累计抑制的字节阈值；-1 表示恢复活动前不强制类别刷新。 |

可配置类别为：

- chunk-stream：区块、光照和区块批次；
- block-updates：方块、批量方块和方块实体更新；
- entity-stream：实体生成、移动、元数据、装备和属性；
- world-effects：声音、粒子、爆炸和世界事件；
- ui-stream：BossBar、Title、TabList、计分板、地图等界面同步。

suppression-whitelist-categories 中的名称必须使用上面的小写键名。字段会在启动时去重、转成小写并忽略未知类别。

进入和退出消息支持传统颜色代码（例如 &7、&a）和十六进制颜色（例如 &#55FFFF）。占位符如下：

| 占位符 | 可用消息 | 含义 |
| --- | --- | --- |
| `{player}` | 进入、退出 | 玩家名称。 |
| `{saved_traffic}` | 退出 | 本次 AFK 会话节省的流量。 |
| `{saved_bandwidth}` | 退出 | 本次 AFK 会话记录的峰值节省带宽。 |

清空消息字符串可以关闭对应提示。管理员可以执行以下命令查看累计统计：

~~~text
/afknetstats
/afknetstats <player>
~~~

命令需要管理员命令权限。若玩家看到客户端短暂不同步，先确认 resync-on-resume 为 true；只有在明确知道某类数据必须持续发送时，才把它加入白名单。

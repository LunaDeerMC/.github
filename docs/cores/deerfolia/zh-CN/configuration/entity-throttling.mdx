## 文件作用

config/kaiiju-entity-throttling.yml 由 Kaiiju 实体节流器读取。它按每个 Folia 区域中的实体数量，为指定类型设定正常更新上限和移除阈值：

- 少于或等于 limit 的实体保持正常每 tick 更新；
- 超过 limit 的实体仍然存在，但超出的更新会被节流，通常不是每个 tick 都执行；
- 超过 removal 后，核心会逐步移除超出范围的实体；
- 没有出现在此文件中的实体类型不受该文件限制。

这里的数量是每个区域的数量，不是整个服务器所有世界的总和。Folia 区域会随着玩家和区块活动变化，所以不要把它当成全局刷怪上限。

## 默认写法

首次启用时，核心会写入类似以下内容：

~~~yaml
ZombifiedPiglin:
  limit: 1000
  removal: 3000

Axolotl:
  limit: 1000
  removal: 3000
~~~

每种实体都由一个同名区块组成。实体名称使用核心启动日志公布的可用名称，例如 ZombifiedPiglin、Axolotl、Villager、IronGolem、Item 和 ExperienceOrb。名称必须与日志中的大小写一致；不要随意填写 Minecraft 命名空间、下划线或带 Entity 后缀的猜测名称。

## 字段详解

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| limit | 至少为 1 | 该实体类型在一个区域内保持每 tick 更新的数量上限。 |
| removal | -1 或大于 limit | 超过该数量后启动逐步移除。-1 表示不按该阈值移除，但仍可节流。 |

如果 removal 小于或等于 limit，且不是 -1，启动时会记录错误并自动按 limit 的 10 倍处理。不要利用这个规则代替明确配置。

## 如何为刷怪场调优

实体节流会影响实体 AI、移动、拾取、繁殖、攻击和掉落等行为，应该按用途设置：

1. 先只给最容易造成区域压力的实体添加条目；
2. 把 limit 设置为测试区域正常运作所需的数量；
3. 把 removal 设置得明显高于 limit，给短时间的实体峰值留出空间；
4. 观察 10–20 分钟的实体数量、CPU、TPS 和农场产出；
5. 发现行为异常时先把对应实体条目移走或临时关闭总开关。

不要为了降低 CPU 而给 Villager、Item、Player 或所有 Mob 设置极低的 limit。交易所、物品分类机、刷怪场和玩家交互都会把“正常多实体”误判成压力。

## 错误与回滚

- 未知实体名称会被记录并跳过，不会自动创建实体类型；
- limit 小于 1 的条目会被忽略；
- YAML 语法错误会阻止该配置正常加载；
- 修改后需要完整重启服务器；
- 回滚时恢复整个文件并重启，不要只删除报错行后继续使用未知状态。

如果不确定某个实体是否应该限制，先关闭 deer-folia.yml 中的 kaiiju-entity-throttling，确认问题消失后再只恢复一个条目。

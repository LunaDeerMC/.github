## 配置文件

DeerFolia 的配置文件位于服务器根目录的 `config/`：

| 文件 | 作用 | 是否由 DeerFolia 读取 |
| --- | --- | --- |
| deer-folia.yml | Dynamic Activation、异步寻路、网络、Lithium、POI 和 AFK 网络等核心优化 | 每次服务器启动时读取 |
| kaiiju-entity-throttling.yml | 按实体类型和区域设置更新上限与移除阈值 | deer-folia.yml 开启实体节流后读取 |

`global`、`world-defaults`、`spigot` 和 `bukkit` 等 Folia、Paper 配置由上游负责。请按上游配置规则修改这些文件。DeerFolia 只读取上表中的文件。

## 配置文件如何生成

DeerFolia 第一次加载配置时会创建 `deer-folia.yml`。`kaiiju-entity-throttling` 为 `true` 时，Kaiiju 限制器还会创建 `kaiiju-entity-throttling.yml`，并写入 `ZombifiedPiglin` 和 `Axolotl` 默认项。

配置管理器会把 Java 字段名转换为 kebab-case 键。例如 `asyncPathfindingMaxThreads` 会变成 `async-pathfinding-max-threads`。启动时会补回缺少的已知键。未知键不会启用 DeerFolia 功能。

## 推荐修改顺序

1. 停止服务器。等待世界保存完成。
2. 复制要修改的文件。在备份名称中加入日期。
3. 只修改一个功能组或一个实体类型。
4. 检查 YAML 缩进、冒号、引号和列表写法。
5. 启动测试服务器。阅读完整日志。
6. 使用玩家、实体密集区域或挂机账号测试。
7. 将测试通过的修改复制到生产服务器。

## 生效方式

DeerFolia 在服务器启动阶段加载这些文件。每次修改后都要重启服务器。不要使用 Bukkit 或 Paper reload 重新加载核心配置。Lithium 优化和异步路径查找必须重启后才会应用。

## YAML 修改注意事项

- YAML 使用空格。不要使用 Tab。
- 布尔值写 `true` 或 `false`。不要加引号。
- 列表项使用短横线。空列表写 `[]`。
- 消息中包含冒号、井号、花括号或颜色符号时使用引号。
- 不要为消除错误删除不熟悉的区段。先恢复最近一次能启动的备份。
- 修改前确认字段单位。单位可能是 tick、区块距离、实体数量或字节。

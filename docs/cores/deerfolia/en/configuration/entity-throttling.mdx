## What the file does

config/kaiiju-entity-throttling.yml is read by the Kaiiju entity throttler. For selected entity types, it sets a normal ticking limit and a removal threshold per Folia region:

- entities at or below limit keep normal per-tick updates;
- entities above limit still exist, but excess updates are throttled and do not run every tick;
- entities above removal are gradually removed;
- entity types absent from the file are not limited by this file.

The count is per region, not a server-wide total across every world. Folia regions change with player and chunk activity, so this is not a global mob cap.

## Default format

When enabled for the first time, the core creates a file similar to:

~~~yaml
ZombifiedPiglin:
  limit: 1000
  removal: 3000

Axolotl:
  limit: 1000
  removal: 3000
~~~

Each entity type is a named section. Use names printed as available by the core startup log, such as ZombifiedPiglin, Axolotl, Villager, IronGolem, Item, and ExperienceOrb. Match the log's capitalization; do not invent names with a Minecraft namespace, underscores, or an extra Entity suffix.

## Fields

| Field | Requirement | Meaning |
| --- | --- | --- |
| limit | At least 1 | Number of that entity type in one region that keeps normal per-tick updates. |
| removal | -1 or greater than limit | Start gradual removal above this count. -1 disables removal by this threshold but still allows throttling. |

If removal is less than or equal to limit and is not -1, startup logs an error and replaces it with limit multiplied by 10. Do not rely on that correction instead of setting a clear value.

## Tuning a farm

Entity throttling can affect AI, movement, pickup, breeding, attacking, and drops. Tune by purpose:

1. add entries only for entity types that create pressure in the target region;
2. set limit to the number required for the test area to work normally;
3. keep removal well above limit to allow short-lived peaks;
4. observe entity count, CPU, TPS, and farm output for 10–20 minutes;
5. remove the entry or disable the master switch when behavior is wrong.

Do not give Villager, Item, Player, or every Mob a very low limit just to reduce CPU. Trading halls, item sorters, farms, and player interactions can make a healthy server look like an overloaded region.

## Errors and rollback

- unknown entity names are logged and skipped;
- limits below 1 are ignored;
- YAML syntax errors prevent normal loading;
- restart the complete server after changes;
- restore the whole file when rolling back instead of deleting one error line and continuing with an unknown state.

If you are unsure whether an entity should be limited, turn off kaiiju-entity-throttling in deer-folia.yml, verify that the symptom disappears, and restore one tested entry at a time.

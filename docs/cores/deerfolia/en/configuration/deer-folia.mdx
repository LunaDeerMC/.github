## Default file

The following is the current source-generated structure. The live file also contains comments; use the file generated by the exact build you are running when fields differ.

~~~yaml
dynamic-activation-brain:
  enabled: true
  start-distance: 12
  activation-distance-mod: 8
  maximum-activation-prio: 20

async-pathfinding:
  enabled: true
  async-pathfinding-keep-alive: 60
  async-pathfinding-max-threads: 20

kaiiju-entity-throttling: true

network-optimizations:
  optimized-var-int: true
  optimized-frame-encoding: true

lithium-optimize:
  enabled: true
  allocations: true
  ai: true
  collections: true
  entity: true
  math: true
  world: true

poi-optimizations:
  enabled: true
  golem-spawn-check-interval: 200
  secondary-poi-sensor-interval: 80
  village-distance-cache-duration: 100
  golem-spawn-player-distance-limit: 128

afk-network-optimization:
  enabled: true
  afk-threshold-ticks: 1200
  afk-enter-message: "&7[AFKNet] &eYou are now AFK. &7DeerFolia will temporarily suppress non-essential packets to save bandwidth."
  afk-exit-message: "&7[AFKNet] &aWelcome back! &7During this AFK session, you saved &b{saved_traffic} &7of traffic and up to &b{saved_bandwidth} &7of bandwidth. &aThanks for helping the server save costs!"
  count-look-changes-as-activity: true
  resync-on-resume: true
  stats-enabled: true
  suppression-whitelist-categories: []
  max-suppressed-bytes-before-category-resync: -1
~~~

## Dynamic Activation of Brain

This group lets entities farther from players tick their AI less often, reducing work when no player is observing the area.

| Key | Default | Meaning |
| --- | ---: | --- |
| enabled | true | Master switch. Disabling it returns to behavior closer to the upstream activation cadence. |
| start-distance | 12 | Distance at which activation frequency begins to fall. |
| activation-distance-mod | 8 | Distance-decay parameter. Lower values usually reduce distant-entity work earlier or more strongly. |
| maximum-activation-prio | 20 | Maximum interval. With 20, a distant entity is still evaluated at roughly least once every 20 ticks. |

If a mob farm, villager hall, or redstone machine shows visible delay, first lower activation-distance-mod or increase start-distance. Change one value at a time and test the affected area.

## Async Pathfinding

This group moves selected pathfinding work into asynchronous tasks, reducing the chance that pathfinding blocks the current region tick.

| Key | Default | Meaning |
| --- | ---: | --- |
| enabled | true | Master switch for async pathfinding. |
| async-pathfinding-keep-alive | 60 | Maximum active lifetime of a path thread, in ticks. |
| async-pathfinding-max-threads | 20 | Async path pool size. The implementation uses virtual threads, not one physical core per configured thread. |

The README recommends a practical range of 10–20. Too few threads can queue work; too many may increase scheduling and GC pressure without a visible gain. If pathfinding becomes unstable or CPU/GC fluctuates, lower the pool size first. Restart after changing these options.

## Kaiiju Entity Throttling

kaiiju-entity-throttling is the master switch. The detailed format is in [Entity throttling](./entity-throttling). When it is false, DeerFolia does not use limits in kaiiju-entity-throttling.yml. The file can remain for a later re-enable, but do not add low limits for every entity without testing.

## Network Optimizations

This group has no separate enabled switch:

| Key | Default | Effect |
| --- | ---: | --- |
| optimized-var-int | true | Optimizes VarInt reads and writes for packet length fields. |
| optimized-frame-encoding | true | Optimizes the network frame encoding path and reduces outbound preparation work. |

These options affect internal packet handling and should not change player-facing features. If a proxy, compression plugin, or protocol problem appears, disable one option at a time in a test copy to identify whether the optimized path is involved.

## Lithium Optimize

This group ports selected Lithium server hot-path optimizations and adapts them to Folia's region-threaded model. enabled is the master switch; the remaining keys select groups:

| Key | Main purpose |
| --- | --- |
| allocations | Reduce temporary allocations in frequently called paths. |
| ai | Optimize entity AI behavior iteration. |
| collections | Use lighter collection access in entity attribute paths. |
| entity | Skip unnecessary entity work and client-only particle logic. |
| math | Use simpler math hot paths that are easier for the JVM to optimize. |
| world | Optimize world generation, weather, and freeze-related paths. |

All of these options require a server restart. They are not the complete Lithium feature set and do not replace optimizations already supplied by Paper, Folia, or Moonrise. If entity, redstone, or weather behavior looks wrong, disable enabled in a test server before changing multiple sub-options.

## POI Optimizations

This group targets villager Point of Interest checks. Values are ticks or block distances:

| Key | Default | Meaning |
| --- | ---: | --- |
| enabled | true | POI optimization master switch. |
| golem-spawn-check-interval | 200 | Minimum interval between iron golem checks per villager, about 10 seconds. |
| secondary-poi-sensor-interval | 80 | Minimum interval between secondary POI scans, about 4 seconds. |
| village-distance-cache-duration | 100 | Village-distance cache duration, about 5 seconds. |
| golem-spawn-player-distance-limit | 128 | Skip part of the golem check when no player is within this distance. |

For large villager areas, start with defaults and observe CPU. If an iron farm or workstation system is sensitive to timing, lower the relevant interval or temporarily disable enabled to compare behavior.

## AFK Network Optimization

When a player is inactive for long enough, DeerFolia suppresses selected non-essential clientbound packets and resynchronizes required state when the player becomes active. This targets bandwidth during AFK sessions; it does not stop the world logic for the player.

| Key | Default | Meaning |
| --- | --- | --- |
| enabled | true | AFK network suppression master switch. |
| afk-threshold-ticks | 1200 | Enter AFK after 1200 inactive ticks, about 60 seconds. |
| count-look-changes-as-activity | true | Treat look-only rotation as activity. |
| resync-on-resume | true | Resend nearby chunks and tracked entities when activity resumes; recommended. |
| stats-enabled | true | Accumulate data used by /afknetstats. |
| suppression-whitelist-categories | [] | Categories that still pass while AFK. |
| max-suppressed-bytes-before-category-resync | -1 | Per-player, per-category byte threshold; -1 means no forced category refresh before activity resumes. |

Supported categories:

- chunk-stream: chunks, light, and chunk-batch data;
- block-updates: block, multi-block, and block-entity updates;
- entity-stream: entity creation, movement, metadata, equipment, and attributes;
- world-effects: sounds, particles, explosions, and world events;
- ui-stream: BossBar, Title, TabList, scoreboard, map, and other UI synchronization.

Names in suppression-whitelist-categories must use the lower-case keys above. Startup normalizes case, removes duplicates, and ignores unknown categories.

Entry and exit messages support legacy colors such as &7 and &a, plus hex colors such as &#55FFFF. Placeholders:

| Placeholder | Available in | Meaning |
| --- | --- | --- |
| `{player}` | entry and exit | Player name. |
| `{saved_traffic}` | exit | Traffic saved during this AFK session. |
| `{saved_bandwidth}` | exit | Peak saved bandwidth recorded for this AFK session. |

Clear a message value to disable that notification. Administrators can inspect totals with:

~~~text
/afknetstats
/afknetstats <player>
~~~

The command requires administrator command permission. If a player sees a short-lived desynchronization, check that resync-on-resume is true before adding categories to the whitelist.

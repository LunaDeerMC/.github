## File map

DeerFoliaPlus core settings live in config/:

| File or directory | Purpose | Load boundary |
| --- | --- | --- |
| config/deer-folia-plus.yml | FakePlayer, strongholds, protocols, recipe sync, posture, and utility switches | Core startup |
| config/custom-recipes.yml | Custom recipe definitions | Loaded when custom-recipe.enabled is true |
| worlds/world-name/fakeplayer.dat | List of saved fake players | World save loading |
| worlds/world-name/fakeplayerdata/ | NBT data for saved fake players | Fake-player save or load |
| syncmatica/litematica/ | Uploaded Syncmatica schematic files | Used when Syncmatica is enabled |
| syncmatica/temp/ | Temporary Syncmatica upload files | During Syncmatica transfers |

Fake-player data follows the world save and is not stored in plugins/. Syncmatica files live in the server-root syncmatica/ directory and should be included with worlds and configuration in backups.

## How files are generated

The core creates config/deer-folia-plus.yml during its first configuration load. Java camelCase names become kebab-case keys: amountPerPlayer becomes amount-per-player, and skipFabricOnViaNonNative becomes skip-fabric-on-via-non-native.

When custom-recipe.enabled is true, the core creates custom-recipes.yml under config/. The default file has no active recipes; add definitions under recipes. If parsing fails, start with the full log rather than deleting the file.

## Recommended edit order

1. stop the server and wait for world saves;
2. back up config/deer-folia-plus.yml, config/custom-recipes.yml, world data, and syncmatica/;
3. change one feature group or one recipe;
4. check YAML indentation, quotes, lists, and namespaces;
5. start the test directory and read the complete log;
6. verify with real players, client mods, and target worlds;
7. move the tested change to production.

## Restart and client boundaries

deer-folia-plus.yml is loaded during core startup. Fully restart after changing it; Bukkit/Paper reload is not a core configuration hot-reload mechanism. Custom recipes are registered during the server load phase, so restart after edits and check the registered count.

Syncmatica, Servux, and Recipe Sync depend on the server switch, client support, and protocol versions together. A server-side true value does not make the feature usable for players without the matching client mod.

## YAML notes

- use spaces, never tabs;
- write booleans as true or false, not quoted strings;
- quote messages, namespaces, and values containing colons;
- use fully namespaced item IDs in custom recipes, such as minecraft:diamond;
- keep a recoverable copy before editing;
- restore the last known-good file first when unknown keys or parsing errors appear.

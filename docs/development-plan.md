# LunaDeerMC 官网完整开发计划与阶段验收

> 本文档把已确认的设计与技术架构拆分为可交付阶段。每个阶段只有在完成对应验收门槛后才能进入下一阶段；聊天中的临时想法不自动扩大阶段范围。

- 最后更新：2026-08-02
- 当前基线：设计与技术架构已确认，正式站点源码尚未建立
- 目标：交付可静态构建、双语、双主题、可访问、可维护并可发布的 LunaDeerMC 官网与文档站

## 1. 全程约束

以下要求适用于每个开发阶段：

- 使用 Astro、Astro Content Collections 和 LunaDeerMC 专用内容领域层，不采用 Starlight，也不重新开发通用静态网站生成器。
- React 只通过按需 Islands 承担需要浏览器状态或高级交互的局部能力，不把全站改成 SPA。
- 中文使用无前缀 URL，英文使用 `/en` 前缀；公共页面按国际化规则生成。
- 所有作品、文档、渠道与成员事实来自权威内容源或站点配置，不在组件中复制或虚构。
- 官方 Logo 只使用 `docs/design/assets/lunadeermc-brand-logo.png` 原始 RGBA 文件。
- 界面与通用语义图标默认使用 Lucide，作品与品牌身份使用登记资产。
- 所有页面支持键盘、窄屏、减少动态和基础无 JavaScript 使用。
- 设计令牌、组件、路由、内容模型或验收规则发生变化时，同步更新对应事实源。
- 不把依赖目录、框架缓存、测试报告或构建产物提交到仓库。

## 3. 阶段 0：仓库与设计基线

### 交付范围

- 初始化 Git 仓库基线与根级忽略规则。
- 提交设计说明、技术架构、权威视觉资产和隔离原型源码。
- 固化首页内容地图、精选作品运行时随机展示、四层视差与页脚过渡决策。
- 建立本开发计划。

### 验收要求

- `main` 存在可追溯的基线提交。
- `node_modules`、`dist`、`.astro`、测试报告和系统缓存未被跟踪。
- 官方 Logo、已确认视觉稿、POC 与设计文档均能从索引定位。
- 已废弃方案被明确标为历史，不与当前事实源冲突。
- 提交完成后工作区没有本阶段遗留修改。

## 4. 阶段 1：工程骨架与内容领域基础

### 交付范围

- 建立根级 Astro、TypeScript、MDX、React、Vitest 与 Playwright 工程。
- 按源码结构文档建立 `src/pages`、`src/content`、`src/lib/content`、`src/i18n`、`src/components`、`src/layouts`、`src/styles` 与 `tests`。
- 建立 `site` 单例配置加载器、`workData`、`workPages` 和 `docs` Content Collections。
- 实现作品、默认作品页和文档 Frontmatter 的 Schema 与标准化类型。
- 建立中文无前缀、英文 `/en` 的静态路由基础。
- 建立统一命令：静态检查、单元测试、生产构建、生产预览和端到端测试。

### 验收要求

- 全新检出后只通过已记录的包管理命令即可安装和运行，不依赖全局私有工具。
- `astro check` 与 TypeScript 检查无错误。
- Content Collections 能加载最小 fixture，并对必填字段、枚举、未知字段和跨文件冲突给出预期错误或警告。
- 同一最小页面能够生成中文 `/` 与英文 `/en`，语言切换链接指向真实路由。
- 生产构建不访问 GitHub Releases、第三方获取平台或其他运行时外部服务。
- Vitest 覆盖作品聚合、文档集识别、永久链接和错误边界。
- CI 可连续执行静态检查、单元测试和生产构建。

## 5. 阶段 2：全站设计系统、导航与页脚

### 交付范围

- 实现颜色、排版、网格、留白、表面、动效和图标令牌。
- 实现 `system | light | dark` 三态主题偏好及本地持久化。
- 实现全站导航的左右语义分组、功能菜单和三级响应式收纳。
- 实现统一页脚的 Horizon Veil、Horizon Veil 的主题配对及三种响应式形态。
- 建立共享页面布局、焦点样式、跳过导航和基础无 JavaScript 内容结构。

### 验收要求

- 浅色与深色使用同一组件结构，只通过语义令牌与场景资产切换。
- 首次访问跟随系统，用户手动选择后能稳定恢复偏好；主题切换不改变滚动位置或页面几何。
- 导航在宽屏、中等宽度和窄屏按已确认顺序收纳，Logo 始终可见。
- 功能菜单可通过键盘打开、关闭和遍历，Escape、焦点返回和可见焦点均正确。
- 页脚桌面使用 Horizon Veil，平板符合 Balanced Midwide，移动端符合 Quiet Footer Ledger。
- 页脚直接使用官方 Logo 原始资产，链接、外链语义和法律底栏完整。
- 代表性导航与页脚状态通过 Playwright、axe 和桌面／平板／移动截图检查。

## 6. 阶段 3：首页与生产四层场景

### 交付范围

- 制作浅色“白天牧场”和深色“黄昏红石工坊”两套生产四层场景。
- 实现真实 DOM Hero、统一滚动进度、远慢近快视差和同色精选作品过渡。
- 实现首页内容顺序：精选作品、等权文档＋支持、关于收束、Quiet Field、Horizon Veil 与页脚。
- 从标准化作品数据生成完整 `featured` 候选集合，并在每次页面加载时随机展示最多三件等权作品。
- 实现无精选候选、无 JavaScript、减少动态和图片加载失败的降级路径。

### 验收要求

- 每个主题的四层资产来自同一场景、同一机位和同一透视关系；静止合成没有断层或互不关联的插画感。
- 背景近似静止，远景、中心叙事层和近景依次加快向上移动；不存在反向或无意横向漂移。
- `scene.foreground` 与 `surface.featured` 使用同一精确颜色，滚动录屏中没有白闪、色缝、硬边或矩形遮罩感。
- 当前显示的精选作品彼此等权；文档与支持入口彼此等权。
- 候选数超过三件时每次页面加载最多显示三件，当前页面生命周期内主题切换和滚动不重新抽样。
- 候选为空时完整省略精选作品内容，同时保持场景到后续内容的视觉连续。
- JavaScript 禁用时仍可看到稳定的最多三件精选回退、Hero 操作和后续全部入口。
- `prefers-reduced-motion: reduce` 使用稳定静态合成场景，内容顺序和操作不变。
- 桌面、平板、移动端和中英文长文本均无裁切、横向溢出或布局跳动。
- 非当前主题和非当前响应式构图的重型场景资源不会抢占首屏关键加载。
- 首页通过固定内容与随机函数注入的端到端测试；视觉回归使用固定抽样结果。

### 阶段边界

- 具体速度、距离和文案退场曲线在真实资产与滚动录屏上校准，不从旧原型复制。
- CSS 透视与变换优先；只有可验证需求证明不足时，才评估动画库、Canvas、WebGL 或 3D。

## 7. 阶段 4：作品目录与作品介绍页

### 交付范围

- 实现作品目录的分类、筛选、搜索协同、URL 状态和空结果。
- 实现作品轻量索引聚合、封面、图标、归档和兼容性呈现。
- 实现默认 `index.mdx` 作品介绍页骨架。
- 实现 `index.astro` 自定义作品主页路由与共有校验边界。
- 实现介绍、图库、版本与更新、获取方式及文档入口。

### 验收要求

- 作品事实只来自标准化作品数据和当前作品页面源，不在列表组件复制。
- 分类、次级筛选和 URL 可刷新、前进、后退与分享。
- 目录项与当前选择状态满足已确认的桌面和移动布局；移动端选择后阅读位置合理。
- 默认作品页只渲染当前作品真实具备的标签页与信息，不显示空模块。
- 访问模式与获取档次通过跨文件校验；付费资源不会被静态产物意外暴露。
- 归档作品、替代作品、缺失文档、空 Release、限流和网络失败均有明确表现。
- 自定义主页成功构建，并保留标题、摘要、主内容、全站入口和基础无障碍能力。
- 代表性的默认页、自定义页、归档页和移动状态通过 Playwright 与 axe。

## 8. 阶段 5：文档目录与文档阅读系统

### 交付范围

- 实现 `/docs` 文档集目录、分类、搜索入口与表格化列表。
- 实现文档集识别、永久链接、独立侧边栏、本页目录、上一篇／下一篇和面包屑。
- 实现 Markdown／MDX 正文组件、代码块、提示、链接与图标规则。
- 实现桌面阅读布局与移动端文档工具栏、侧边栏抽屉和本页目录。

### 验收要求

- 每个文档集的侧边栏和上一篇／下一篇严格限制在当前文档集与当前语言内。
- 文档永久链接、标题锚点、站内链接、图片和下载资源在构建阶段校验。
- 文档目录不展示章节树，阅读页不混入其他作品的文档树。
- 缺少对应语言的文档不生成目标页面，并进入对应语言的 404。
- 桌面三栏与移动工具栏都能通过键盘和触控完整操作，抽屉焦点管理正确。
- 正文行长、标题层级、代码块溢出、表格和长链接在代表性内容上通过视觉检查。
- 代表文档集通过中英文、桌面、移动、无 JavaScript、axe 与链接验证。

## 9. 阶段 6：支持、关于与辅助页面

### 交付范围

- 实现支持中心的四条等权路径和四个长滚动区段。
- 实现关于页的手册式索引、组织介绍、理念、成员、开源、合作与品牌资源。
- 实现 404、隐私政策、使用条款与其他通用辅助页面入口。
- 接入站点配置中的社区、邮箱、GitHub、第三方平台和品牌资源。

### 验收要求

- 支持页四条路径与锚点可直接访问，并能把用户引导到正确渠道；不建立工单或站内联系表单。
- 支持页不把赞助与付费获取混为一谈，外部平台和政策具有清楚边界。
- 关于页只使用成员自愿公开的信息，不虚构统计、履历或企业化宣传。
- Logo 下载与展示都使用已登记资产，品牌使用说明与法律政策职责不混淆。
- 长滚动章节在桌面和移动端保持已确认节奏，固定导航与锚点偏移正确。
- 404 保持当前语言、主题和主要返回路径；基础页面均具有中英文版本。

## 10. 阶段 7：搜索、索引、SEO 与全站输出

### 交付范围

- 在 Astro 生产构建后生成 Pagefind 索引。
- 实现桌面快速搜索、窄屏完整搜索和独立搜索结果页。
- 输出 sitemap、robots、canonical、双语对应链接和页面级 SEO 元数据。
- 完成作品、文档、支持内容的搜索元数据与范围过滤。

### 验收要求

- 中文、英文和常见 Minecraft 技术词能返回正确结果。
- 当前文档集打开搜索时优先展示当前范围，并可显式切换全站范围。
- 搜索结果明确区分作品、文档和支持，不显示草稿或受保护内容。
- 搜索在键盘、触控、窄屏、空结果和无索引错误状态下都可理解。
- sitemap 中只包含公开且真实生成的路由；canonical 与语言对应关系正确。
- Pagefind 缺失或客户端脚本失败时，站点主体和直接导航仍可使用。

## 11. 阶段 8：集成验收、发布与维护基线

### 交付范围

- 完成全站内容、设计、功能、性能、无障碍和浏览器兼容审计。
- 建立正式 CI、生产部署、缓存、重定向、回滚和发布检查。
- 固化生产性能预算、浏览器矩阵和视觉回归基线。
- 编写内容维护、作品发布、文档新增、品牌资产与故障处理说明。

### 验收要求

- 完整构建顺序通过：内容校验、`astro check`、Vitest、Astro 构建、Pagefind、产物验证、Playwright 与 axe。
- Chromium、Firefox 和 WebKit 通过关键路径；桌面与移动代表视口无阻断缺陷。
- 自动化 axe 无 Critical 或 Serious 问题；人工键盘、焦点、屏幕阅读语义和减少动态检查通过。
- 生产预览在约定的 Lighthouse 环境达到项目最终性能、可访问性、最佳实践和 SEO 预算。
- 首屏只加载当前主题与当前断点所需关键资源，无显著 CLS、长任务或横向溢出。
- 所有公开页面均有正确标题、摘要、语言、主题、404、站内链接与外链语义。
- 部署失败可以回退至上一稳定产物；发布不依赖第三方实时 API 成功。
- 实际生产内容完成双语、权限、隐私、法律和品牌使用复核。

## 12. 跨阶段验收方法

每个阶段的完成报告至少包含：

1. 本阶段交付与未交付范围。
2. 修改过的事实源和代码入口。
3. 实际执行的检查命令及结果。
4. 桌面、平板、移动和必要交互状态的视觉证据。
5. 已知风险、延期项和下一阶段依赖。

“页面能够打开”不等于阶段完成。只有内容来源、主题、语言、响应式、键盘、减少动态、无 JavaScript 降级和阶段专属测试都满足对应门槛时，才可以关闭阶段。

## 13. 当前明确不进入首轮范围

- 官网内付款、订单、交付或退款处理。
- 站内工单系统、即时聊天或联系表单后台。
- 通用 CMS、通用静态站点生成器或面向外部发布的内容框架。
- 全量 React SPA、第二套客户端 UI 框架或无设计需求支持的全局 3D。
- 为追求视觉效果而提前引入 Canvas、WebGL、Shader、GSAP、Motion 或 React Three Fiber。
- 无限滚动、用户账户、评论、评分、下载统计或个性化推荐系统。

这些能力未来只有在出现真实需求、内容模型和验收标准后才进入新的设计与开发阶段。

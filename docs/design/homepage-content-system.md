# 首页内容系统

> 本文档定义 LunaDeerMC 首页的内容顺序、区块职责、精选作品生成规则和页面末段收束。首页视觉场景与视差关系由[首页视觉方向](./homepage-visual-direction.md)维护。

- 最后更新：2026-08-02
- 状态：内容地图、区块职责、等权关系与精选作品展示规则已确认

## 总体内容顺序

首页保持轻量，并按以下固定顺序组织：

```text
全站导航
→ 四层场景 Hero
→ 精选作品（存在精选候选时）
→ 文档＋支持
→ 简短的组织介绍
→ Quiet Field
→ Horizon Veil
→ 统一页脚
```

页面叙事依次回答“我们是谁、做了什么、如何使用、去哪里获得帮助、为什么持续做这些事”。该顺序不表示同一区块内部存在主次关系。

浅色、深色、中文、英文和所有响应式形态保持相同的信息顺序。主题与语言只改变视觉资产或文案，不改变内容职责。

## Hero

Hero 保留以下真实 DOM 内容：

```text
LunaDeerMC

To the moon, to the dream, to the future!

为 Minecraft 社区构建可靠易用的插件、
服务端核心与开发工具。

[浏览作品]  [查看文档]
```

- `浏览作品` 进入作品目录。
- `查看文档` 进入文档目录。
- Hero 可以提供轻量向下滚动提示。
- 不展示统计数字、新闻、价格、代码编辑器、服务器 HUD 或完整功能清单。
- 所有文字、导航和操作保持为可访问 DOM，不烘焙进场景图片。

## 精选作品

### 内容来源

首页不维护作品名称、摘要或手工精选名单。候选集合由内容领域层从 `src/content/works/{work}/data.yaml` 聚合：

- 只有 `featured: true` 的作品进入候选集合。
- 名称来自 `name`。
- 当前语言摘要来自 `summary.zh-CN` 或 `summary.en`。
- 类型、访问模式、生命周期、图标和封面分别来自对应索引字段。
- 作品目录名生成稳定的作品介绍页 URL。
- 首页不读取 `index.mdx` 或 `index.astro` 的正文来拼装条目。

### 展示规则

- 候选集合为空时，完整省略精选作品区块，不渲染空标题、占位卡片或虚构作品。
- 候选集合为一至三件时，展示全部候选并随机排列。
- 候选集合超过三件时，每次页面加载随机抽取三件并随机排列。
- 随机抽样发生在浏览器展示阶段；静态构建必须保留完整候选集合，不能在构建时永久截断为三件。
- 同一次页面加载只抽样一次。滚动、视口尺寸变化和主题切换不重新抽样。
- 语言切换如果产生完整页面导航，可以在目标页面重新抽样。
- JavaScript 不可用时仍提供稳定、可访问且最多三件的静态回退内容；回退不依赖随机性才能理解。

随机展示只影响当前页面中可见的候选与顺序，不改变作品索引数据、作品目录顺序、搜索结果或作品列表页。

### 等权排版

- 当前显示的每件作品使用相同的封面比例、标题层级、摘要预算、元数据和入口样式。
- 不使用“一件主作品＋若干次级作品”的构图，不放大第一件作品，也不为某一件设置旗舰位置。
- 条目可以通过开放网格、等权列表、留白和细分隔线建立节奏，不形成悬浮卡片墙。
- 首页只展示理解作品所需的轻量信息，不展开完整功能、兼容性、获取渠道、价格或版本历史。
- 区块提供统一的“浏览全部作品”入口。

## 文档＋支持

文档与支持属于同一个宏观章节，并作为两个等权入口呈现：

- 两者拥有相当的空间、标题层级、说明长度和操作重量。
- 桌面端可以形成对称的开放双列；窄屏按阅读顺序纵向排列，但不通过尺寸或表面制造主次。
- 不渲染为两张强阴影或高圆角的功能卡片。

### 文档职责

- 帮助用户从安装、配置进入深入使用。
- 进入文档目录，不在首页重复完整分类树、文档集列表、章节目录或最近文章。
- 不展示可能快速过期的文档数量统计。

### 支持职责

- 帮助用户进入社区与交流、获取与授权、赞助与支持、法律与政策等正确路径。
- 进入支持中心，不在首页展开群号、邮箱、第三方平台、赞助方式或政策目录。
- 不在首页建立工单、联系表单或长篇常见问题。

## 关于收束

关于区是首页最后一个真实内容区，承担简短的品牌与组织收束：

- 说明 LunaDeerMC 对可靠作品、清楚交互和可复用知识的长期关注。
- 可以使用“做值得长久使用的作品，也认真记录抵达它的每一步”作为当前文案基线。
- 只提供一个“了解 LunaDeerMC”入口。
- 不重复关于页中的完整组织介绍、开发理念、成员、开源、合作与品牌资源。

## 页脚过渡

关于区之后依次进入 Quiet Field、Horizon Veil 和统一页脚：

- Quiet Field 只负责降低阅读强度，不增加新功能或宣传内容。
- Horizon Veil 只承担场景过渡，不叠加页脚文案。
- 页脚结构、响应式形态和品牌资产规则以[全站页脚系统](./footer-system.md)为准。
- 精选作品区块因无候选而省略时，四层场景的前景融合仍需自然衔接后续内容，不能留下空舞台、色缝或布局断层。

## 验收标准

- 所有主题、语言和断点保持相同内容顺序。
- 精选作品全部来自标准化作品索引，首页源码不硬编码作品事实。
- 当前展示作品彼此等权，文档与支持入口彼此等权。
- 每次页面加载最多显示三件精选作品；同一页面生命周期内不自行重抽。
- 无精选候选时区块完整省略，后续内容与场景过渡仍连续。
- JavaScript 失败时 Hero、最多三件精选回退内容、文档、支持、关于和页脚仍可访问。
- 首页不承担完整作品目录、文档目录、支持渠道或关于页正文。

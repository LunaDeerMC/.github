# 全站主题策略

> 本文档定义 LunaDeerMC 官网的双主题行为与页面适用边界。视觉方向已经确认，精确色值仍由颜色系统和后续视觉稿确定。

- 最后更新：2026-08-02
- 状态：全站双主题方向已确认

## 总体结论

全站通用页面支持浅色与深色双主题：

```text
浅色与深色双主题
├── 首页 /
├── 支持 /support
├── 关于 /about
├── 作品列表 /works
├── 默认作品介绍页 /works/{work}，入口为 index.mdx
├── 文档 /docs/**
├── 搜索 /search
├── 404
└── 其他通用页面

页面自主决定
└── 自定义作品介绍页 /works/{work}，入口为 index.astro
```

首页的主题切换具有最完整的品牌表达：

- 深色模式使用“黄昏红石工坊”四层场景。
- 浅色模式使用“白天牧场”四层场景。

支持、关于、作品和文档不必复制首页场景，但需要继承同一套深浅主题的颜色、材质、排版和交互语言。

## 主题选择与记忆

通用页面提供“跟随系统、浅色、深色”三个主题偏好。首次访问默认为“跟随系统”；用户手动选择后，使用浏览器本地持久化存储记住选择。

```ts
type ThemePreference = "system" | "light" | "dark";
type EffectiveTheme = "light" | "dark";
```

有效主题按以下规则计算：

```text
preference = light  → 显示 light
preference = dark   → 显示 dark
preference = system → 根据 prefers-color-scheme 显示
不存在有效本地值    → 视为 system
```

- 控件显示用户偏好，而不是推导后的有效主题。
- 本地只接受 `system`、`light`、`dark`，其他值安全回退为 `system`。
- `system` 模式需要监听系统主题变化。
- 手动浅色或深色模式不被系统变化覆盖。
- 其他标签页修改偏好后，已打开页面同步更新。
- 首屏绘制前完成主题判断，避免错误主题闪烁。

## 首页双场景

主题切换不仅替换 CSS 颜色，还会切换完整的四层场景资产组：

```text
dark/
├── sky
├── distance
├── settlement
└── foreground

light/
├── sky
├── distance
├── farm
└── foreground
```

两套场景必须保持：

- 相同的页面结构、Hero 内容、导航位置和可操作入口。
- 相同的层数、场景容器高度和运动语义。
- 对应的文案安全区，避免切换后文字压住主体。
- 对应主题中“近景主体色＝精选作品背景”的同色关系。
- 不发生布局跳动、滚动位置重置或内容顺序变化。

两套场景不要求拥有同一建筑、同一地形或相同色调。白天牧场必须是独立制作的场景，不能通过滤镜从黄昏工坊派生。

主题切换时的具体资产过渡方式尚未确认。无论采用即时替换还是短交叉淡化，都不能同时显示两套场景造成重影。

## 支持与关于

- 两个页面同时支持浅色和深色，不再固定为夜间品牌模式。
- 深色继承黄昏红石工坊的暖炭褐、陶瓦、红铜和红石珊瑚关系。
- 浅色继承白天牧场的燕麦、草地、天空和深森林文字关系。
- 页面可以拥有自己的静态环境媒体，但不能建立第三套无关品牌配色。
- 布局、信息密度与最终场景用法仍待单独讨论。

## 作品、文档与搜索

- 两种主题下保持相同的信息层级、内容顺序和交互能力。
- 默认作品介绍页使用全站语义令牌，不允许 Frontmatter 绕开统一主题。
- 文档正文、代码块、表格、提示块、侧边栏、目录和搜索结果分别校验两种主题。
- 浅色阅读界面以暖白、燕麦或浅石为基础，不使用刺眼纯白。
- 深色阅读界面以暖炭褐为基础，不复刻首页的高强度场景。
- 主题切换不改变路由、筛选状态、搜索范围或阅读位置。

## 自定义作品页

使用 `index.astro` 的自定义作品介绍页拥有独立视觉自治：

- 可以固定浅色、固定深色、支持双主题或采用作品专属配色。
- 必须在自身设计说明中明确主题行为。
- 离开自定义页面后，全站保存的主题偏好继续生效。
- 仍需满足文本对比度、键盘焦点和 `prefers-reduced-motion` 等底线。

## 主题控件

- 提供“跟随系统”“浅色”“深色”三个互斥选项。
- 使用完整文本或等价的可访问名称，不能只依赖太阳和月亮图标。
- 控件位于导航的功能菜单中；精确形式由导航系统确定。
- 主题变化不应阻止滚动、点击或键盘操作。

## 设计令牌边界

通用页面必须使用语义令牌：

```text
surface.canvas
surface.subtle
surface.raised
surface.featured
text.primary
text.secondary
text.muted
border.default
accent.primary
accent.on-primary
focus.ring
code.background
scene.foreground
```

- 浅色和深色为同一组令牌提供不同取值。
- 首页可增加场景资产令牌，但不能污染普通内容组件。
- 自定义作品页可使用局部令牌，但不能覆盖其他页面的全局值。
- 精确命名、色值和透明度由[全站颜色系统](./color-system.md)继续确定。

## 实现要求

- 首屏绘制前应用正确主题和对应场景，避免颜色或图片闪切。
- 主题偏好、系统监听和跨标签同步使用一份全站共享实现。
- 场景资产切换不能删除或覆盖用户偏好。
- 主题变化不能重置页面滚动位置。
- 语法高亮、图片、远程封面和第三方嵌入分别检查两种主题。
- 控件具有可访问名称、键盘操作和明确当前状态。

## 尚待确定

- 弹层、禁用状态、代码块等扩展表面的具体色值与对比度目标。
- 首页两套场景切换时是否使用短交叉淡化。
- 已确认的支持、关于、作品目录和文档目录视觉参考在正式实现中的双主题光学校准。
- 代码高亮的浅色和深色配色。

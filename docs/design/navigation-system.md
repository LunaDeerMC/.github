# 全站导航系统

> 本文档定义 LunaDeerMC 官网全站导航的信息分组、主题外观、功能菜单、响应式收纳顺序与滚动状态。

- 最后更新：2026-07-29
- 状态：结构、主题边界、响应式收纳顺序与滚动状态已确认

## 总体结论

全站使用一套统一的导航内容结构和交互模型：

```text
[LunaDeerMC  支持  关于]              [作品  文档  功能菜单]
        组织与品牌                         内容与工具
```

- `LunaDeerMC` 品牌标识始终链接到首页，不再增加单独的“首页”文字入口。
- `支持`、`关于` 与 Logo 左对齐，共同构成组织与品牌入口。
- `作品`、`文档` 与功能菜单右对齐，共同构成内容与工具入口。
- 两组之间依靠宽阔留白和对齐关系形成层级，不使用两个厚重容器或大面积胶囊进行分组。
- 法律与政策不进入顶部导航，继续由支持中心和页脚引导至通用文档。
- GitHub、社区、购买平台和其他外部渠道不直接挤入顶部导航。

## 一套结构，两种外观

导航不维护两套相互独立的组件。它使用相同 DOM 结构、空间骨架、交互规则和可访问性实现，只根据页面职责切换视觉外观。

导航存在两种页面职责，并分别适配浅色和深色：

```text
品牌外观
├── 浅色
└── 深色

内容外观
├── 浅色
└── 深色
```

### 品牌外观

用于首页、支持和关于：

- 响应全站浅色或深色偏好；首页同时切换“白天牧场”与“黄昏红石工坊”场景。
- 初始视觉可以透明并融入页面场景，不把整条导航放入独立卡片或大型磨砂容器。
- 文字、图标和表面根据场景安全区使用语义令牌，交互反馈保持克制。
- 页面滚动后的背景、分隔和可读性变化由后续滚动状态设计确定。

### 内容外观

用于作品列表、默认作品介绍页、文档、搜索和其他通用页面：

- 同时支持浅色与深色。
- 两个主题保持相同高度、间距、布局、入口顺序和点击区域。
- 背景、文字、边框、悬停、焦点和弹层使用语义设计令牌适配，不在组件中直接判断白色或黑色。
- 浅色与深色只是同一内容外观的主题状态，不复制一套导航实现。

### 自定义作品页

自定义 `index.astro` 作品介绍页拥有独立视觉自治，但仍需提供可识别的全站返回和内容入口。它可以复用全站导航并选择合适外观，也可以根据作品设计实现专属导航；无论采用哪种形式，都不能破坏全站主题偏好或让用户失去返回 LunaDeerMC 官网的路径。

## 功能菜单

导航右端使用一个紧凑图标表示功能菜单。视觉上优先使用四点网格或同类“工具集合”图标，不使用容易被理解为“溢出操作”的省略号。

宽屏状态下，菜单只包含工具：

```text
搜索站内内容

语言
中文  English

外观
跟随系统  浅色  深色
```

- 搜索在所有使用全站导航的页面中提供。
- 语言切换在所有使用全站导航的页面中提供，允许在中文和英文之间切换。
- 语言名称分别使用自身语言书写为 `中文` 与 `English`，不使用国旗代替语言。
- 中文页面保持无前缀 URL，英文对应页面使用 `/en` 前缀；切换时优先进入当前页面的对应翻译。
- 显式 URL 决定当前语言，浏览器缓存中的偏好不能强制改写用户直接打开的链接。
- 不使用长期存储记忆语言；站内导航延续当前 URL 的语言上下文，语言切换本身通过目标 URL 生效。
- 仅在中文首页首次会话且浏览器首选语言不是中文时，可显示轻量英文版本提示；提示不自动跳转、不阻断首屏，并用 `sessionStorage` 避免同一会话重复出现。
- 除文档外的所有页面都必须存在另一语言版本；文档缺少对应翻译时，切换后直接进入目标语言的 404，不寻找最近的已翻译祖先。
- 主题模式在所有全站双主题页面中显示，包括首页、支持和关于。
- 自定义作品页只有在明确接入全站主题能力时才显示这组控件。
- 主题模式展示用户选择的 `system | light | dark` 偏好，而不是只展示当前推导出的明暗结果。
- 菜单在桌面端支持悬停预览、点击固定、键盘聚焦和 `Escape` 关闭。
- 移动端不依赖悬停，功能菜单必须可以通过点击完整操作。

页面布局应声明导航与主题能力，例如：

```ts
type NavigationAppearance = "brand" | "content";
type ThemeCapability = "dual" | "custom";
```

不能只根据 URL 字符串临时判断是否显示主题设置，否则自定义作品页和后续新增页面会被路径规则错误限制。

### 菜单呈现

功能菜单始终从右上角图标附近展开，保持明确的空间来源。它不在中等宽度突然变成侧边抽屉，也不从与触发图标无关的屏幕底部出现。

#### 宽屏

- 使用锚定在图标下方的紧凑浮层，建议宽度约为 `280–320px`，精确尺寸在视觉令牌阶段确定。
- 菜单包含搜索、语言切换和主题模式；自定义主题页面可以按自身约定省略全站主题模式。

#### 中等宽度

- 继续使用右上角锚定浮层，不切换为侧边栏。
- 浮层增加“内容”分组，展示已经从导航栏收起的作品和文档入口。
- 搜索、语言切换与主题模式放在独立的“工具”区域，不与页面入口混成一个无层级列表。

#### 窄屏

- 使用导航栏下方、左右保留少量边距的近全宽浮层。
- 浮层按“组织、内容、工具”分组展示当前已收起的入口。
- 页面背景仍从浮层周围轻微露出，避免菜单变成完全不同的第二个页面。
- 菜单打开时阻止背景页面滚动；关闭后恢复原来的滚动位置。
- 不显示仍然留在导航栏中的重复入口。

### 菜单交互

- 带悬停能力的桌面指针设备在短暂延迟后显示菜单预览，避免鼠标偶然经过立即触发。
- 点击功能图标可以固定菜单，使鼠标在图标和浮层之间移动时不会关闭。
- 未固定的悬停菜单在指针离开触发器与浮层后延迟关闭，不能要求用户沿极窄路径移动。
- 键盘聚焦可以打开菜单，`Escape` 关闭菜单并把焦点交还给触发图标。
- 窄屏只通过点击开关菜单，不模拟悬停。
- 选择主题后菜单保持打开，便于用户观察和比较状态。
- 选择搜索后关闭功能菜单，再打开全站统一搜索界面。
- 功能菜单展开时，导航表面立即进入稳定且足够不透明的状态。
- 品牌页面菜单固定使用深色外观；内容页面菜单跟随当前浅色或深色主题。

## 当前页与链接反馈

导航链接使用文字明暗和短线表达当前页面，不使用实心胶囊、明显按钮底色或改变布局的字重切换。

### 当前页面

- 当前入口使用完整文字亮度，并在文字下方显示约 `1px` 的短线；短线明显短于文字宽度。
- 字号、字重、字符间距和点击区域不因当前状态改变，避免导航宽度跳动。
- `/works/**` 标记“作品”，`/docs/**` 标记“文档”，`/support` 与 `/about` 分别标记对应入口。
- 首页不为 Logo 增加下划线；Logo 本身和首页场景已经能够说明当前位置。
- 品牌外观使用柔和月光色标记，内容外观使用当前主题对应的低饱和强调色，两者保持相同语义而不强制使用完全相同的色值。

### 悬停与按下

- 非当前入口在悬停时由柔和文字色过渡到完整亮度。
- 悬停可以显示比当前页状态更淡的短线预览，但不能与当前页标识同等醒目。
- 不使用上浮、缩放、强发光或实心背景表达普通文字链接悬停。
- Logo 悬停只轻微改变明暗，不放大、旋转或产生弹跳。
- 点击与触控按下反馈保持轻量，不能造成文字或导航布局位移。

### 键盘焦点

- 键盘导航使用独立的 `:focus-visible` 轮廓，不能只依赖当前页短线。
- 焦点环与文字或图标保留少量间距，同时在品牌深色、内容浅色和内容深色三种状态中保持清晰对比。
- 鼠标点击不长期显示键盘焦点环，但不能移除元素的程序性焦点。
- 焦点状态以可识别性优先，不能为了视觉克制而降低到难以看见。

### 折叠菜单中的当前页

- 入口进入功能菜单后，当前页面使用高亮文字和左侧短标记，并设置 `aria-current="page"`。
- 功能菜单图标本身不因当前页面位于菜单内而长期显示选中，否则容易被误解为菜单已经打开。
- 菜单关闭时，页面标题、面包屑或文档侧边栏继续承担更精确的位置说明。

普通明暗、短线和标记过渡建议保持在约 `140–180ms` 的克制范围内；精确时长在视觉稿与交互验证阶段确定。启用 `prefers-reduced-motion` 时直接切换状态，不依赖位移动画表达反馈。

## 滚动状态

导航在滚动过程中只改变表面，不改变几何结构与可见性：

```text
品牌页面
└── 页面顶部透明 → 滚动后形成稳定深色表面

内容页面
└── 首帧已有主题表面 → 滚动后轻微增强层次

所有页面
└── 不自动隐藏、不因滚动缩高、不移动入口
```

### 品牌页面

首页、支持和关于在页面顶部时，导航覆盖在场景上方：

- 完全透明，或只使用极轻的顶部暗化渐变保证基础对比度。
- 不显示独立导航容器、阴影或明显边界。
- 开始滚动后，在一小段连续距离内逐渐增加低透明度深色背景、轻微背景模糊和极淡底部分隔。
- 导航表面变化按滚动距离连续完成，不在进入第二屏或第三屏时突然切换。
- 返回页面顶部后自然恢复透明状态。

这一规则让首页四层视差场景保持沉浸感，同时避免导航在不同亮度的画面上失去可读性。

### 内容页面

作品、文档、搜索和其他通用页面从首帧开始使用当前主题对应的稳定导航表面：

- 浅色使用略带冷灰的浅色表面，深色使用墨蓝或月夜黑的深色表面。
- 页面滚动后只轻微增加背景不透明度和底部分隔层级。
- 不从完全透明状态开始，避免页面标题和正文穿过导航时产生干扰。
- 不在向下滚动时隐藏，确保作品、文档、搜索和主题入口始终可找到。

### 几何稳定性

- 同一响应式阶段内，导航高度、Logo、文字和功能菜单位置不随滚动变化。
- 不使用滚动后缩小 Logo、压缩高度或改变左右内边距的效果。
- 窄屏同样保持导航可见；文档局部工具栏占用空间的问题在阅读布局中单独解决，不能通过让全站导航表现得不可预测来规避。
- 功能菜单展开时，导航表面立即进入稳定且足够不透明的状态；菜单关闭后再根据当前滚动位置恢复对应表面。
- 页面内锚点和文档标题定位必须计算固定导航高度，不能让目标内容被遮挡。
- `prefers-reduced-motion` 启用时可以直接切换表面或使用极短淡变，不依赖连续滚动动画表达状态。

## 响应式收纳顺序

导航根据实际可用宽度逐级收纳，不简单地按“桌面、平板、手机”设备名称切换，也不在当前阶段写死像素断点。

### 第一阶段：完整导航

空间充足时展示全部入口：

```text
[LunaDeerMC  支持  关于]              [作品  文档  功能菜单]
```

功能菜单包含搜索，以及双主题页面中的主题模式。

### 第二阶段：先收起内容入口

空间开始紧张时，优先将 `作品`、`文档` 收入功能菜单：

```text
[LunaDeerMC  支持  关于]                         [功能菜单]
```

此时菜单内容为：

```text
内容
作品
文档

工具
搜索
语言
主题模式（仅双主题页面）
```

这一优先级成立的原因是：首页 Hero 已经提供醒目的“浏览作品”和“查看文档”入口，而支持与关于没有同等重量的替代入口。保留支持与关于也能在中等宽度下维持组织身份。

### 第三阶段：再收起组织入口

只有在手机等非常窄的空间中，才进一步将 `支持`、`关于` 收入功能菜单：

```text
[LunaDeerMC]                                      [功能菜单]
```

此时菜单完整展示：

```text
组织
支持
关于

内容
作品
文档

工具
搜索
语言
主题模式（仅双主题页面）
```

Logo 始终保留。若最终品牌字标在极窄宽度下仍显拥挤，可以使用已经过品牌设计确认的紧凑字标或图形标识，不能临时裁切或缩放到难以辨认。

### 断点原则

折叠顺序固定为：

```text
完整导航
→ 收起作品、文档
→ 再收起支持、关于
→ Logo 始终保留
```

- 精确断点应在 Logo、字体、字号和导航间距确定后，根据内容即将拥挤的宽度测量得出。
- 菜单中不重复展示当前仍在导航栏中可见的入口。
- 折叠和展开不能改变分组名称、入口顺序或页面含义。
- 触控目标、键盘顺序、焦点管理和屏幕阅读器名称在三种状态下都必须完整。

## 连续性要求

- 品牌外观与内容外观保持相同的导航高度、Logo 锚点、左右分组逻辑、字体比例和功能菜单位置。
- 页面切换时只改变表面材质、颜色与必要的工具内容，不交换左右分组或重新排序入口；语言切换始终保留在工具区。
- 导航在品牌页面与内容页面之间切换时，首帧必须直接呈现当前有效主题，不能先闪现另一主题。
- 当前页状态使用文字明暗、短线或其他轻量方式表达，不使用大面积实心胶囊。
- 菜单弹层遵循当前有效主题；品牌页面和内容页面都支持浅色与深色。

# 首页视觉方向

> 本文档固化已经确认的首页空间结构，并将尚未确认的视觉方案、素材和参数明确隔离。旧版水域、倒影与连续摄影机方案已废弃。

- 最后更新：2026-08-02
- 状态：结构、双主题场景、内容衔接与开发前运动语义已确认；正式素材和精确动效参数待实现校准
- 参考：[Material for MkDocs 首页](https://squidfunk.github.io/mkdocs-material/)

原型隔离在 `prototypes/homepage-duskmoon/`。它只用于验证我们是否理解了交互意图，不是正式首页实现，也不是视觉稿。

## 已确认的双主题场景

首页为浅色和深色主题分别制作一套完整的四层场景，不通过滤镜从同一张图派生。

### 深色模式：黄昏红石工坊

![黄昏红石工坊参考](../../prototypes/visual-directions/theme-dark-redstone-dusk.png)

- 暖色黄昏中的红石工程工坊和开发者聚落。
- 主要气质是创造、可靠、专注与克制的技术感。
- 场景以深暖炭褐、陶瓦、红铜、红石珊瑚和少量灯光构成。
- 近景深暖主体色延续为深色精选作品舞台。

### 浅色模式：白天牧场

![白天牧场参考](../../prototypes/visual-directions/theme-light-sunlit-pastoral.png)

- 晴朗白天中的牧场、麦田、农舍、谷仓、草坡和远山。
- 主要气质是清新、开放、安定和友好。
- 场景以天空蓝、自然草绿、麦穗金、燕麦色和浅石构成。
- 近景麦田／燕麦基底延续为浅色精选作品舞台。

两张图片是视觉气质和页面关系参考，不是最终生产资产。图片中的具体建筑、构图细节、作品名称与场景辅助色仍可调整；已经确认的界面语义色板不随参考图细节任意漂移。

## 1. 已确认的核心概念

首页借鉴 Material for MkDocs 首页的场景组织与视差逻辑，但把场景替换为原创的 Minecraft 世界。

首屏由一个统一场景拆成四个景深层。用户向下滚动时，背景近似静止，另外三个景物层同时向上移动，并遵循**远景慢、近景快**的速度关系。近景逐渐占据视口，使人感到观察视角正在降低，最后自然进入实心配色的“精选作品”区。

```text
统一的 Minecraft 场景
  ├─ 背景／天空：近似静止或最慢
  ├─ 远景：慢速向上
  ├─ 中景：中速向上
  └─ 近景：最快向上
             ↓
近景颜色连续扩展为精选作品背景
```

这里的“四层”指同一机位、同一透视关系中的空间切片，不是四张独立插画的叠放，也不是多个场景之间的切换。

## 2. 已确认的空间与运动关系

建议的语义分层如下，具体景物随主题变化：

| 层级 | 空间职责 | 运动感知 |
| --- | --- | --- |
| 背景层 | 天空、云、日月或极远轮廓 | 近似静止，或只产生极小位移 |
| 远景层 | 远山、森林、聚落或牧场远端 | 慢速向上 |
| 中景层 | 工坊／农舍、道路、田地等主题叙事中心 | 中速向上 |
| 近景层 | 植被、岩石、地形边缘等贴近观察者的主体 | 最快向上，并最终接管画面 |

所有活动层都应随向下滚动而向上，不应出现某层反向移动。速度差需要让近景明显比远景快，但不能大到让图层彼此脱离。

“视角降低”的错觉来自近景比远景更快地升入并占据视口，而不是整张画面等速上移，也不是在页面上横向扫过一条深色遮罩。

## 3. 已确认的同色过渡

首页必须建立一个共享颜色令牌：

```text
scene.foreground = surface.featured
```

最前景底部的连续主体色、场景末端的融合层和“精选作品”区背景必须使用同一最终色值。页面向下滚动时，近景由图像内容逐渐变为纯色画布，二者之间不能出现可辨认的色缝或新颜色。

深色和浅色主题分别拥有自己的 `scene.foreground` 与 `surface.featured` 取值。每个主题内部的两个颜色必须完全相同，主页双主题交互原型中的具体色号已经确认。

已确认的 v1 基线为：

```text
dark  scene.foreground = surface.featured = #1F1211
light scene.foreground = surface.featured = #F6E5C7
```

色板的完整职责、对比度和调整边界由[全站颜色系统](./color-system.md)维护。正式四层场景应以这两个前景色为制作目标；如果资产色彩管理造成可辨色缝，必须成对校准场景前景与作品舞台，而不能只改其中一侧。

过渡应由近景自身的连续色块和底部融合共同完成，不使用独立的整屏遮罩、硬切或无关渐变。

## 4. 首屏内容

首屏保留以下真实 DOM 内容：

- 全站导航：LunaDeerMC、支持、关于、作品、文档和功能菜单。
- `LunaDeerMC`。
- `To the moon, to the dream, to the future!`
- `为 Minecraft 社区构建可靠易用的插件、服务端核心与开发工具。`
- `浏览作品` 与 `查看文档`。
- 轻量向下滚动提示。

文案、导航和按钮不得烘焙进场景图片。首屏不展示统计、价格、代码编辑器或服务器 HUD。

## 5. 素材必须满足的条件

正式四层素材必须从**同一个 Minecraft 场景和同一个机位**制作，再拆分为独立通道。可以采用游戏内搭建后渲染、Blender 场景渲染或其他能保证空间一致性的流程；不应分别生成四张互不关联的图片再强行拼接。

每层必须满足：

- 共享相同的地平线、透视、光源方向、时间氛围和色彩关系。
- 透明边缘干净，景物轮廓自然穿插，不形成整齐的水平矩形带。
- 保留足够的上下延展和安全裁切区，滚动时不露空白边缘。
- 近景底部形成连续、足量的主体色，但仍保留自然地形轮廓。
- 不出现悬浮岛式断面、突兀的地块截面或层间无法对齐的建筑。
- 桌面与移动端可以使用同一场景的不同构图或单独导出，而不是只靠 `object-position` 勉强裁切。

正式制作介质尚未确认，可以采用经过美术指导的游戏内渲染、Blender 场景或克制的方块插画。无论采用哪种介质，都必须保留已选定的双主题气质，并首先保证统一机位与可信空间。

## 6. 精选作品区

精选作品采用实心舞台，舞台颜色与首屏近景主体色完全一致。

- 当前显示的作品彼此等权，使用相同的封面比例、标题层级、摘要预算、元数据和入口样式。
- 不采用“一件主作品＋若干次级作品”的构图，不放大第一件，也不设置旗舰位置。
- 候选作品由标准化作品索引中的 `featured: true` 生成；首页不硬编码作品事实。
- 浏览器每次加载首页时从完整候选集合中随机展示最多三件，同一页面生命周期内滚动和主题切换不重新抽样。
- 没有精选候选时完整省略精选作品内容，但场景前景仍需自然衔接后续章节。

首页完整内容顺序、文档与支持的等权关系、无 JavaScript 回退及页面末段收束由[首页内容系统](./homepage-content-system.md)维护。当前原型中的主次作品布局已经明确废弃，不应写入正式实现约束。

## 7. 参考机制与待校准参数

Material for MkDocs 使用内部纵向滚动容器和 CSS 透视空间。其参考层深度为 `8 / 5 / 2 / 1`，通过 `translateZ()` 和相应缩放形成远慢近快的视觉速度。

这些数值只用于理解机制和建立下一轮校准起点，不是 LunaDeerMC 的最终参数。最终速度应以我们的场景尺寸、构图和真实滚动录屏为准。

实现原则：

- 所有图层属于同一个坐标系统，由一个统一的滚动进度驱动。
- 优先保证“远慢、近快”和层间不脱节；具体技术可以在实现阶段选择。
- 两个主题保持相同的场景容器尺寸、层数和运动语义，切换主题不能引发布局跳动或重置滚动位置。
- Hero 内容可以在短距离内淡出，但不能掩盖层次运动是否正确。
- `prefers-reduced-motion: reduce` 时显示稳定的静态合成场景，内容回到正常文档流。

## 8. 当前原型的结论

当前原型成功验证了三件事：

1. 我们理解的是“四层 Minecraft 单一场景”，而不是水面或多场景切换。
2. 首屏会通过差速滚动进入实心的精选作品区。
3. 精选作品背景需要继承近景主体色。

当前原型没有通过视觉验收：

- 图层速度关系和体感不正确，没有形成可信的远慢近快。
- 四张素材不像同一场景、同一机位下的分层，空间无法严密对齐。
- 深色前景形成横贯屏幕的矩形带，滚动时像遮罩切片。
- 地块边缘呈悬浮岛断面，破坏了“视角降低”的连续感。
- 图片画风、构图和整体美术质量未达到预期。

因此，现有图片和参数都不是设计事实，不能沿用到正式页面。原型仅作为“交互意图已理解”的证据保留。

## 9. 响应式与无障碍

- 桌面端保留完整四层关系；移动端重新安排焦点和文案位置。
- 图像、脚本或动画失败时，导航、标题、说明和入口仍可访问。
- 页面必须防止横向溢出，按钮和标题不能因语言或窄屏裁切。
- 减少动态模式取消视差和装饰性循环动画，但不改变信息顺序。

## 10. 防偏离约束

- 不恢复水面、倒影、岸线或连续摄影机方案。
- 不把四层场景改成多张全屏图淡入淡出。
- 不把各层作为互不相关的插图独立制作。
- 不把白天牧场做成黄昏红石工坊的提亮或滤镜版本。
- 不将精选作品背景改成与近景不一致的颜色。
- 不使用横贯视口的硬边矩形前景充当过渡。
- 不加入玻璃大卡片、代码窗口、像素字体、粒子或青紫霓虹光晕。

## 11. 验收标准

- 静止时，四层看起来属于一个完整、可信的 Minecraft 场景。
- 向下滚动时，背景近似静止，远景慢、中景适中、近景最快地向上移动。
- 近景接管画面的过程读作观察视角降低，而不是图层切片或遮罩扫过。
- 场景与精选作品之间没有明显色缝、白闪、硬边或突兀色块。
- 精选作品区与最前景底部使用同一精确颜色。
- 移动端与减少动态模式均可完整访问内容。

## 任务是什么

选点完成后，建造或拆除操作会提交为一个**任务**，进入智能队列分帧执行。插件把大量方块操作分摊到多个游戏刻，避免一帧卡死服务器，同时实时向玩家反馈进度。

## 任务状态

| 状态 | 含义 |
| :--- | :--- |
| 运行中 | 正在逐帧处理方块 |
| 已暂停 | 因材料不足、额度不足等原因挂起，可手动继续 |
| 已取消 | 被玩家或管理员取消 |
| 已完成 | 全部方块处理完毕 |

每个方块的结果分为三类：**成功**、**跳过**（如被保护插件拦截、工具不匹配）、**失败**。任务完成时会在聊天栏汇总：`任务完成：成功 <n>，跳过 <n>，失败 <n>`。

## 任务菜单

打开 `/eb` → 任务菜单，可以看到：

- **任务摘要**：状态、类型、处理进度（已处理 / 总数）、成功 / 跳过 / 失败数量；
- **继续任务**：恢复被暂停的任务；
- **取消任务**：取消当前任务（不可恢复）。

## 暂停与恢复

任务可能在以下情况自动暂停：

| 暂停原因 | 说明 | 如何处理 |
| :--- | :--- | :--- |
| 材料不足 | 建造消耗背包方块，材料不够时暂停 | 补充材料后到任务菜单点「继续任务」 |
| 额度不足 | 公平用量计划的配额耗尽 | 额度刷新后继续，参见[公平用量](../features/fair-usage) |
| 玩家离线 | 任务所有者在任务期间下线 | 重新上线后继续（取决于管理员配置，可能直接取消） |
| 保护拦截 | 大量方块被保护插件拒绝 | 检查领地 / 权限后继续 |
| 连续失败 | 失败次数达到 64 次 | 检查选点和配置后继续 |
| 区块卸载 / Folia 区域不安全 | 目标区域不在安全执行范围 | 回到对应区域后继续 |

**恢复方式**：打开 `/eb` → 任务菜单 → 继续任务。

> **注意**：材料不足暂停的恢复需要**手动点击继续**（默认配置下不会自动恢复）。每个玩家最多同时挂起 **3 个**暂停任务；达到上限后新的暂停任务会被直接取消。

## 运行限制

| 限制 | 默认值 | 说明 |
| :--- | :---: | :--- |
| 每玩家同时运行任务数 | 1 | 已有运行中任务时，新提交会被拒绝 |
| 每玩家暂停任务数 | 3 | 超过上限的暂停任务会被取消 |
| 单次操作最大方块数 | 10000 | 超限提交会被拒绝 |
| 每玩家每刻方块数 | 2 | 基准速度，受工具亲和性影响 |
| 全服每刻方块数上限 | 512 | 所有玩家共享 |
| 每刻处理时间预算 | 2ms | 防止任务拖垮服务器 tick |

## 材料消耗

- 放置操作**真实消耗背包中的方块**（创造模式与拥有豁免权限的玩家除外）；
- 消耗顺序：背包存储槽 →（开启「消耗潜影盒」时）背包内潜影盒中的同类方块，详见[从潜影盒消耗材料](../features/shulker-consume)；
- 拆除操作消耗主手工具耐久（生存模式，效率附魔按原版规则减免）；
- 材料不足时任务暂停而不是失败，这正是「建筑助力」而非「刷方块作弊」的体现。

## 常见问题

**任务卡在暂停状态，点继续也没反应？**

如果已经有一个任务在运行，恢复操作会被拒绝（运行任务上限为 1）。先等当前任务完成或取消，再继续暂停的任务。

**为什么任务处理得很慢？**

每玩家每刻的基础额度是 2 个方块，持有效率附魔的工具（或配置调高 `blocks-per-tick-per-player`）可以显著提速。拆除速度同时受工具亲和性倍率影响。

**下线后任务会怎样？**

默认配置下任务会**暂停**（玩家离线原因），重新上线后可继续；管理员可以配置为直接取消（`cancel-task-when-player-offline`）。

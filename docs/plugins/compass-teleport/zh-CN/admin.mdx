## 安装与首次启动

1. 停止服务器，并备份世界、`plugins/` 目录和服务端日志。
2. 从 [CompassTeleport GitHub Releases](https://github.com/LunaDeerMC/CompassTeleport/releases) 下载 JAR。
3. 将 JAR 放入服务端的 `plugins/` 目录。目录中只保留一个 CompassTeleport JAR。
4. 启动服务器，确认控制台显示插件已成功启用。
5. 首次启用后检查 `plugins/CompassTeleport/config.yml`。修改配置后重启服务器。插件没有配置重载命令。
6. 用一个没有 OP 的测试账号完成绑定、重命名和传送，再向普通玩家开放。

## 配置文件

默认配置如下：

~~~yaml
cooldown-sec: 15
delay-sec: 5
cost-level: 1
~~~

| 配置键 | 默认值 | 作用 |
| --- | ---: | --- |
| `cooldown-sec` | `15` | 每名玩家完成一次传送处理后，需要等待多少秒才能再次使用。 |
| `delay-sec` | `5` | 从右键空气触发到执行传送前等待的秒数。设为 `0` 时仍会保留很短的内部调度等待。 |
| `cost-level` | `1` | 在铁砧中重命名磁石指南针时设置的经验等级花费，不是每次传送消耗的经验。 |

如果服务器已经存在 `config.yml`，插件会继续使用该文件中的值。请以该文件为准。

## 权限节点

| 权限节点 | 默认值 | 控制内容 |
| --- | --- | --- |
| `compassteleport.use` | `true` | 允许玩家使用已经制作好的传送指南针。 |

这个节点只在玩家右键空气尝试传送时检查。它不会阻止玩家右键磁石绑定指南针，也不会阻止玩家在铁砧中重命名。若只希望特定玩家使用传送，请在权限插件中关闭普通组的默认继承，再单独授予该节点。

## 管理与排查建议

- 先用普通玩家账号验证。OP 账号可能绕过权限插件的实际限制。
- 如果没有传送提示，确认物品是插件生成的铁砧结果。然后确认玩家拥有 `compassteleport.use`。
- 如果提示指南针已失效，确认磁石仍然存在，指南针仍然追踪磁石，目标世界已经加载。
- 如果传送开始但没有完成，记录服务端核心、配置值和完整控制台日志，再在测试服务器中复现。
- `cooldown-sec` 和未完成的传送任务保存在内存中。重启插件或服务器会清除之前的玩家冷却状态。

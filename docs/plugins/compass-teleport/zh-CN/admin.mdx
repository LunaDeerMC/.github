## 安装与首次启动

1. 停止服务器，并备份世界、`plugins/` 目录和服务端日志。
2. 从 [CompassTeleport GitHub Releases](https://github.com/LunaDeerMC/CompassTeleport/releases) 下载适合当前 Minecraft 版本的 JAR。
3. 将 JAR 放入服务端的 `plugins/` 目录；不要同时放入多个版本。
4. 启动服务器，确认控制台显示插件已成功启用。
5. 首次启用后检查 `plugins/CompassTeleport/config.yml`。修改配置后重启服务器；当前项目没有提供配置重载命令。
6. 用一个没有 OP 的测试账号完成绑定、重命名和传送，再向普通玩家开放。

`plugin.yml` 声明的 API 版本为 `1.20`，并标记 `folia-supported: true`。仓库 Maven 配置使用 Java `21` 编译目标；如果自行构建，请使用 Java 21 工具链。正式服务器仍应以目标 Minecraft 版本的服务端运行时要求为准。

## 配置文件

配置文件由源码中的配置类生成。当前 `v1.4.1` 源码默认值如下：

~~~yaml
cooldown-sec: 15
delay-sec: 5
cost-level: 1
~~~

| 配置键 | 默认值 | 作用 |
| --- | ---: | --- |
| `cooldown-sec` | `15` | 每名玩家完成一次传送处理后，需要等待多少秒才能再次使用。 |
| `delay-sec` | `5` | 从右键空气触发到执行传送前等待的秒数。设为 `0` 时仍会保留很短的内部调度等待。 |
| `cost-level` | `1` | 在铁砧中重命名磁石指南针时设置的经验等级花费，不是每次传送消耗的经验。 |

仓库 README 中曾列出 `cooldown-sec: 12` 和 `delay-sec: 3`，但当前 `v1.4.1` 源码配置类的默认值是 `15` 和 `5`。如果服务器已经存在旧的 `config.yml`，插件会继续使用文件中的现有值；请以服务器实际生成的配置文件为准。

## 权限节点

| 权限节点 | 默认值 | 控制内容 |
| --- | --- | --- |
| `compassteleport.use` | `true` | 允许玩家使用已经制作好的传送指南针。 |

这个节点只在玩家右键空气尝试传送时检查。它不会阻止玩家右键磁石绑定指南针，也不会阻止玩家在铁砧中重命名。若只希望特定玩家使用传送，请在权限插件中关闭普通组的默认继承，再单独授予该节点。

## 管理与排查建议

- 先用普通玩家账号验证，不要只用 OP 账号；OP 可能绕过权限插件的实际限制。
- 如果没有传送提示，先确认物品是插件生成的铁砧结果，并检查玩家是否拥有 `compassteleport.use`。
- 如果提示指南针已失效，检查磁石是否仍存在、指南针是否仍在追踪该磁石，以及目标世界是否正常加载。
- 如果传送开始但没有按预期完成，记录服务端版本、插件版本、配置值和完整控制台日志，再在测试服务器中复现。
- `cooldown-sec` 与未完成的传送任务保存在运行时内存中；重启插件或服务器后不会恢复之前的玩家冷却状态。

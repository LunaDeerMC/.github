## Requirements

- A Paper or Folia server; the plugin declares the Minecraft `1.20` API and marks itself as Folia-supported.
- The target Minecraft version should match the plugin and server core. The Maven project compiles against Paper API `1.21.1` with Java 17 as its source and target version; the runtime Java requirement is still determined by the server core.
- The server process must be able to read `plugins/` and write the plugin data directory.

## Obtain and install

If the repository provides a release for the target server, get it from [GitHub Releases](https://github.com/LunaDeerMC/ExpExtraction/releases). When no suitable release is available, build from source:

```sh
git clone https://github.com/LunaDeerMC/ExpExtraction.git
cd ExpExtraction
mvn clean package
```

Put the resulting `target/ExpExtraction-1.3.2.jar` in the server's `plugins/` directory, then fully restart the server. Do not put the plugin JAR in `mods/`, and do not keep multiple versions of the same project in the plugin directory.

After the first successful start, check that the following file exists:

```text
plugins/ExpExtraction/config.yml
```

Run `/extract 1` in game as a small smoke test and confirm that the bottle can be created and used.

## Permission

The plugin declares one permission node:

| Permission | Purpose | Default |
| --- | --- | --- |
| `expextraction.extract` | Use `/extract` | `true` |

The current enchanting-table event does not check this permission separately. Restricting the node therefore restricts the command path but does not, by itself, prevent players from using an enchanting table with an empty glass bottle.

## Configuration

The default configuration has this structure:

```yaml
commandExtraction:
  enable: true
  maximum: 2000

enchantingTable:
  enable: true
  amount: 100
```

| Setting | Default | Purpose |
| --- | ---: | --- |
| `commandExtraction.enable` | `true` | Controls command extraction; the current enchanting-table event checks it too |
| `commandExtraction.maximum` | `2000` | Maximum amount stored by `/extract` in one bottle |
| `enchantingTable.enable` | `true` | Written to the config, but not read by the current `1.3.2` enchanting-table event |
| `enchantingTable.amount` | `100` | Amount the enchanting-table path attempts to extract; it is reduced when the player has less |

Fully restart the server after editing the configuration. The current project does not document a dedicated config-reload command, and replacing the file while the server is running is not recommended.

### Current configuration boundary

To disable both bottle-creation paths, set `commandExtraction.enable` to `false`. The bottle-use event does not check this switch, so existing bottles can still be used.

Changing only `enchantingTable.enable` does not reliably disable enchanting-table extraction in the current version; this is a known mismatch between the generated field and the event implementation.

## Upgrades and troubleshooting

Stop the server before upgrading and back up the current JAR, `plugins/ExpExtraction/config.yml`, and the server log. Replace the JAR, restart, and run a small command extraction and enchanting-table test after the plugin reports that it is enabled.

When troubleshooting, check:

1. the JAR is in `plugins/` and the server log reports the plugin as enabled;
2. the server is Paper/Folia and its Java runtime satisfies the server core;
3. `/extract` has the `expextraction.extract` permission;
4. table extraction has all four conditions: sneaking, an empty glass bottle, right-clicking an enchanting table, and enough experience;
5. the server was fully restarted after configuration changes rather than only partially reloading plugins.

## 环境要求

- Paper 或 Folia 服务端。
- 服务器进程需要能够读取 `plugins/` 并写入插件数据目录。

## 获取和安装

如果仓库提供了适合当前服务端的发行文件，可以从 [GitHub Releases](https://github.com/LunaDeerMC/ExpExtraction/releases) 获取。没有合适发行文件时，可以从源码构建：

```sh
git clone https://github.com/LunaDeerMC/ExpExtraction.git
cd ExpExtraction
mvn clean package
```

构建完成后，将 `target/` 中生成的 JAR 放入服务器的 `plugins/` 目录，然后完全重启服务器。不要把插件 JAR 放进 `mods/`。插件目录中只保留一个 ExpExtraction JAR。

首次成功启动后，检查以下文件：

```text
plugins/ExpExtraction/config.yml
```

随后在游戏内使用 `/extract 1` 做一次小额测试，并确认经验瓶能够生成和使用。

## 权限

插件声明的权限节点只有一个：

| 权限节点 | 用途 | 默认值 |
| --- | --- | --- |
| `expextraction.extract` | 使用 `/extract` 命令 | `true` |

附魔台提取事件没有单独检查这个权限。因此，限制该权限只能限制命令路径，不能单独阻止玩家通过潜行和空玻璃瓶使用附魔台。

## 配置文件

默认配置结构如下：

```yaml
commandExtraction:
  enable: true
  maximum: 2000

enchantingTable:
  enable: true
  amount: 100
```

| 配置项 | 默认值 | 作用 |
| --- | ---: | --- |
| `commandExtraction.enable` | `true` | 控制命令提取；附魔台事件也会检查这一项 |
| `commandExtraction.maximum` | `2000` | `/extract` 单瓶最大经验值 |
| `enchantingTable.enable` | `true` | 配置文件中会生成，但附魔台事件不会读取它 |
| `enchantingTable.amount` | `100` | 附魔台每次尝试提取的经验值；不足时按玩家剩余经验降低 |

修改配置后请完全重启服务器。插件没有单独的配置重载命令。不要在服务器运行时直接覆盖配置文件。

### 配置行为

如果希望关闭创建经验瓶的两条路径，应将 `commandExtraction.enable` 设置为 `false`。由于经验瓶使用事件不检查这个开关，已经存在的经验瓶仍然可以被玩家右键使用。

如果只将 `enchantingTable.enable` 改为 `false`，附魔台提取不会关闭。配置字段和事件实现使用的设置不同。

## 升级和排查

升级前请停止服务器，并备份现有 JAR、`plugins/ExpExtraction/config.yml` 和服务器日志。替换 JAR 后重新启动，确认日志显示插件已启用，再用命令和附魔台各进行一次小额测试。

遇到问题时，优先确认：

1. 确认插件 JAR 位于 `plugins/`，且服务端日志显示插件已启用；
2. 确认服务端为 Paper 或 Folia，Java 满足服务端核心要求；
3. 确认 `/extract` 拥有 `expextraction.extract` 权限；
4. 确认附魔台操作同时满足潜行、空玻璃瓶、右键附魔台和足够经验；
5. 确认修改配置后已完整重启，而不是只重载部分插件。

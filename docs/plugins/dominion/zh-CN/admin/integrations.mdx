## 集成职责

Dominion 的外部能力分成几个相互独立的层次：数据库负责保存数据，Vault 负责经济服务，WorldGuard 负责区域冲突协作，Residence 迁移负责一次性导入，PlaceholderAPI 负责向其他插件提供显示数据，跨服务器功能则负责共享数据库、跨服缓存和跨服传送。

具体配置请阅读：

- [PlaceholderAPI](./placeholderapi)：完整占位符清单、参数形式、显示示例和排错方法。
- [跨服务器功能](./multi-server)：代理、共享数据库、服务器 ID、缓存同步、跨服传送和迁移顺序。

## 数据库

`config.yml` 支持 `sqlite`、`mysql`、`mariadb` 和 `pgsql`。

- SQLite 免维护、适合单服；不要在多个服务器实例之间共享同一个 SQLite 文件。
- 外部数据库适合需要独立备份、监控或多服共享数据的部署；先验证账号权限、网络和连接池。
- 修改数据库类型前先使用 `/dominion export db` 并保留原数据库；`/dominion import db confirm` 只能用于迁移或恢复，不用于合并两套数据库。
- 数据库密码属于敏感信息，不能放进公开仓库、问题截图或公开日志。

数据库连接成功只代表插件可以访问数据，不代表服务端策略已经正确。上线前仍要用普通账号验证领地边界、成员、flag、传送点和子领地关系。

## Vault 与经济插件

`limitations/*.yml` 的 `economy.enable` 开启后，需要 Vault 或兼容的 VaultUnlock，以及实际可用的经济插件。费用按匹配到的限制文件决定：可以按方块收费、只计算水平面积、设置收缩/删除退款比例，以及设置子领地免费创建。

如果控制台提示找不到 Vault 或经济服务，先确认依赖加载顺序、经济插件已经注册服务、玩家余额充足，再检查当前玩家匹配的限制文件。经济开关只影响费用，不会替代领地数量或尺寸校验。

## WorldGuard

WorldGuard 是可选软依赖。它与 Dominion 都可能监听方块、实体或区域事件；当两个插件对同一事件有不同判断时，应在最小化插件集和普通账号下复现，并查看事件优先级与取消来源。

不要因为“能创建领地”就认为两个插件的所有规则已经自动合并。生产服应明确哪一个插件负责出生点、建筑权限、爆炸和区域重叠，再通过小型测试区验证冲突行为。

## Residence 迁移

Residence 迁移需要在 `config.yml` 打开 `residence-migration`，并使用 `migrate` 或 `migrate_all`。建议先迁移一个小型测试区，核对世界、X/Y/Z 边界、所有者、子领地和关键 flag；迁移不是实时同步，原插件数据应保留到确认完成之后。

详细命令与回滚顺序见[管理员命令](./commands)和[迁移与备份策略](./upgrade)。

## 服务端平台

切换服务端核心后，检查启动日志中的 NMS 后端。出现 UI 回退或事件异常时，先确认后端已加载，再排除其他插件。完成创建、权限、事件和传送测试后，再开放服务器。

## 集成问题的共同排查顺序

1. 记录 Dominion、服务端核心、Java 和可选依赖等运行环境信息；
2. 确认插件在启动日志中完成启用，并且依赖在正确时机加载；
3. 使用普通账号在单独测试领地中复现；
4. 暂时移除无关插件，判断是 Dominion 规则还是事件冲突；
5. 保留完整日志与脱敏后的相关配置，再提交问题反馈。

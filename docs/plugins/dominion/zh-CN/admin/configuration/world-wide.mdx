## world-wide 的作用

领地 flag 只在已认领区域内生效；`world-wide` 用于给未认领区域设定一套世界级默认规则。例如，管理员可以让大厅世界的未认领区域禁止放置和破坏，也可以在资源世界开放部分生物或爆炸行为。

文件位于 `plugins/Dominion/world-wide/`，文件名通常对应世界名：

```text
plugins/Dominion/world-wide/
├── default.yml
├── world.yml
└── resource.yml
```

未列出具体世界时使用 `default.yml`。管理员绕过逻辑优先于 world-wide 规则，因此应使用普通账号验证最终效果。

## 文件格式

```yaml
enabled: false
flag-schema-version: 2
environment:
  monster_spawn: false
  tnt_explode: false
  show_border: true
privilege:
  move: true
  pick_up: true
  drop_item: true
  place: false
  break: false
  container: false
```

`flag-schema-version` 当前为 `2`，由插件用于迁移旧 flag 名称或结构，不要为了绕过提示手工改成插件版本号。`environment` 与 `privilege` 的键名来自 [`flags.yml`](./flags)，只填写当前版本存在的 flag。

## 与领地内规则的区别

当玩家进入已认领区域时，插件优先使用该领地/子领地的 guest、member 或 group 设置；world-wide 不是父领地，也不会把未认领区设置“继承”到新建领地。新建领地的默认值仍来自 `flags.yml` 与插件的领地数据逻辑。

因此，建议用以下测试矩阵确认配置：

| 位置 | 账号 | 应检查的规则 |
| --- | --- | --- |
| 未认领区域 | 普通玩家 | `world-wide.privilege` 和 `environment` |
| 已认领根领地 | 访客 | 领地 guest flag |
| 已认领根领地 | 成员/组成员 | member 或 group flag |
| 已认领子领地 | 普通玩家 | 子领地自身规则与父领地边界 |
| 任意位置 | 管理员 | `admin-bypass` 是否符合预期 |

## 使用步骤

1. 先复制当前生成的 `default.yml`，不要从旧版本手工拼接 flag。
2. 用世界名创建或修改对应的 YAML 文件。
3. 只调整需要的 flag，保持 `enabled` 与 `flag-schema-version` 存在。
4. 执行 `/dominion reload config`，查看控制台加载结果。
5. 用普通玩家在未认领区域测试放置、破坏、容器、移动和目标环境事件。

如果发现世界级规则没有生效，先确认玩家站在未认领区域、文件名与世界名一致、`enabled: true`，再检查是否被管理员权限或其他插件绕过。删除 `default.yml` 会失去兜底配置，不建议这样做。

## 文件头与数据库

`version` 是插件用来识别配置格式的内部版本，当前为 `4`。它不是插件版本号，也不是给管理员填写的配置；不要手工修改。

```yaml
version: 4
database:
  type: sqlite                 # sqlite、mysql、mariadb、pgsql
  host: localhost
  port: '3306'
  database: dominion
  username: dominion
  password: dominion
  connection-pool-size: 10
```

SQLite 不需要远程主机、账号或密码，但这些键仍会保留在生成文件中。使用外部数据库时，应先创建数据库与账号，再填写对应连接信息，并在测试服确认字符集、网络、权限和连接池容量。密码属于敏感信息，不要把包含真实密码的配置提交到公开仓库或截图中。

## 多服模式

```yaml
multi-server:
  enable: false
  server-name: server
  server-id: 1
```

开启后，`server-name` 应与 BungeeCord/Velocity 等代理中的服务器名保持一致；`server-id` 必须为正整数，且在所有共享数据库的服务器之间唯一。一旦数据库已经写入数据，不要随意更改 `server-id`，否则可能造成数据归属混乱。SQLite 不支持多服模式，插件检测到这种组合时会自动关闭多服模式并记录错误。完整部署顺序见[跨服务器功能](../multi-server)。

## 语言和 UI

```yaml
language: en_us
ui:
  default: CHEST
```

`language` 对应 `plugins/Dominion/languages/` 中的语言文件名；当前发行版包含 `en_us` 与 `zh_cn` 等语言文件。`ui.default` 只接受 `CHEST` 或 `DIALOG`，它决定没有个人 UI 偏好的玩家使用哪种界面。玩家自己的选择可通过 `/dominion ui chest`、`/dominion ui dialog` 覆盖；`/dominion ui default` 恢复默认值。

## 创建、清理与距离

```yaml
auto-create-radius: 10
auto-clean-after-days: 180
server-spawn-protection-radius: 10
minimum-dominion-distance: 0
select-tool: ARROW
info-tool: STRING
```

- `auto-create-radius` 是 `/dominion auto_create` 使用的半径；`-1` 关闭自动创建。
- `auto-clean-after-days` 用于清理长期未登录玩家的领地；`-1` 关闭自动清理。启用前应确认服务器的玩家活跃周期和备份策略。
- `server-spawn-protection-radius` 防止玩家在出生点附近创建领地。
- `minimum-dominion-distance` 控制领地之间的最小距离；`0` 表示不额外要求间隔。
- `select-tool` 是选点工具，默认 `ARROW`；`info-tool` 是点击领地显示信息的工具，默认 `STRING`。必须填写有效的 Bukkit Material 名称，否则插件会回退到默认值并记录警告。

## 消息显示

```yaml
plugin-message:
  default-enter-message: '&3{OWNER}: Welcome to {DOM}!'
  default-leave-message: '&3{OWNER}: Leaving {DOM}...'
  no-permission-display-place: ACTION_BAR
  enter-leave-display-place: ACTION_BAR
```

`{OWNER}` 会替换为领地主人，`{DOM}` 会替换为领地名称。两个显示位置支持 `BOSS_BAR`、`ACTION_BAR`、`TITLE`、`SUBTITLE`、`CHAT`。颜色代码沿用服务端消息格式；修改后应使用普通玩家测试“允许”和“拒绝”两种消息，避免只验证进入/离开提示。

## 边界显示

```yaml
border-display:
  border-block-material: WHITE_STAINED_GLASS
  crossing-particle-type: END_ROD
  boundary-particles-per-edge-block: 4.0
```

编辑或创建领地时，`border-block-material` 用于临时边界显示；跨过边界时使用 `crossing-particle-type` 产生提示。`boundary-particles-per-edge-block` 是每条边每个方块长度的粒子密度，当前默认 `4.0`，建议先在小型测试领地观察客户端性能，再逐步调高或调低。材质和粒子名称必须来自目标服务端支持的 Bukkit 类型。

## 迁移、管理员绕过与组称号

```yaml
residence-migration: false
admin-bypass: true
group-title:
  enable: false
  prefix: '['
  suffix: ']'
```

- `residence-migration` 控制 Residence 数据迁移能力。迁移完成后应关闭开关，并按[管理员命令](../commands)核对结果。
- `admin-bypass` 为 `true` 时，拥有 `dominion.admin` 的玩家通常会绕过领地限制和规则检查；这也是为什么 OP 账号不能代表普通玩家进行权限测试。若关闭，管理员也会受到正常规则影响。
- `group-title.enable` 开启后，玩家可以把组名显示为称号；`prefix`、`suffix` 定义包裹文本。这个功能只影响显示，不等于权限组文件中的 `priority`。

## 外部链接、飞行与调试

```yaml
external-links:
  command-help: ''
  documentation: https://dominion.lunadeer.cn/notes/doc/player/
fly-permission-nodes:
- essentials.fly
- cmi.command.fly
- domfly.use
check-update: true
debug: false
timer: false
```

`external-links` 用于命令帮助和文档跳转；本网站的文档是面向当前版本重新整理的说明，不会改变插件内置链接的实际值。`fly-permission-nodes` 中的权限节点玩家不会受到 Dominion 飞行限制影响，需根据服务器实际使用的飞行插件调整。`check-update` 控制联网检查更新；排查问题时可临时打开 `debug`，`timer` 是性能记录器，不建议在日常生产环境开启。

## 修改后如何生效

```text
/dominion reload config
```

重载后查看控制台是否报告配置解析、数据库或 flag 加载错误。修改插件 JAR、Java、服务端核心、数据库类型或多服拓扑时，应完整重启；不要用配置重载代替这些操作。

## 文档基准与阅读方式

这套文档按 Dominion `4.9.1-release` 的当前源码、发行构建和测试服生成文件重新整理，并在 Paper `26.2` 上实际启动核对。项目旧 `docs` 仍然适合了解历史设计，但其中部分命令、配置键和 flag 列表已经跟不上当前版本；本文遇到差异时，以当前插件生成的文件、启动日志和游戏内实际提示为准。

文档分为两个互相独立、又可以交叉查阅的部分：

- [玩家文档](./player)：面向普通玩家、领地主人和领地成员，说明如何选择区域、创建领地、邀请成员、设置权限和使用两种 UI。
- [管理员文档](./admin)：面向服主与运维人员，说明安装、数据库、配置文件、flag、限制、跨服、迁移、备份和故障排查。

如果你只是想马上开始使用，可以先看[玩家文档总览](./player)；如果你正在部署服务器，建议从[管理员文档总览](./admin)和[安装与升级](./admin/installation)开始。

## Dominion 解决什么问题

Dominion 把一个 Minecraft 领地拆成四个可以分别管理的对象：

| 对象 | 作用 | 典型设置位置 |
| --- | --- | --- |
| 领地边界 | 保存世界、三维坐标、父子层级和传送点 | 游戏内 UI 或 `/dominion` 命令 |
| 环境规则 | 控制生物、爆炸、火焰、流体、红石相关环境行为 | `flags.yml` + 领地环境 flag |
| 成员权限 | 控制访客、成员、权限组对方块、容器、交互、移动和战斗的权限 | 领地 UI、成员、权限组、模板 |
| 服务端策略 | 控制数据库、创建限制、经济、全世界规则和 UI 默认值 | `config.yml`、`limitations/`、`world-wide/` |

这种拆分意味着“玩家能不能打开箱子”和“领地里能不能生成怪物”是两类不同的设置。修改权限前，先判断问题属于领地边界、成员身份、权限 flag，还是服务端限制，能避免在错误的配置文件里反复尝试。

## 当前版本范围

- Dominion：`4.9.1-release`。
- 本次现场截图：Minecraft `26.2` 客户端 + Paper `26.2` 服务端；NMS 日志确认使用 `v26_2`，Dialog 后端已加载。
- 构建声明的 Minecraft 范围：`1.20.1–1.20.6`、`1.21.x`、`26.1.2–26.2`。
- 服务端平台：Bukkit、Spigot、Paper、Folia；实际生产环境建议优先使用 Paper，并在正式升级前先做完整备份和小范围验证。
- Java：项目使用 Java 17 toolchain；不同 Minecraft 版本的运行时要求仍应以对应服务端核心为准。

## 重要的安全边界

领地删除、所有权转移、数据库导入和配置迁移都可能造成不可逆或大范围影响。执行这些操作前应先导出数据库或复制 `plugins/Dominion/`，不要把测试服上验证过的限制直接复制到生产服。`/dominion delete` 和 `/dominion give` 的二次确认不是装饰，它们用于防止误操作。

管理员拥有的 `dominion.admin` 默认可以绕过领地限制和部分权限判断，但这不等同于“普通玩家拥有所有权限”。如果管理员需要测试访客行为，请使用没有 OP、没有 `dominion.admin` 的测试账号，或者让管理员配置后让普通账号实际验证。

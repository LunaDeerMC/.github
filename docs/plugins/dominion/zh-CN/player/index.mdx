## 核心工作流

Dominion 提供从区域选择、成员协作到环境保护的领地工作流：

1. 选择两个角点，创建一个三维领地；
2. 查看边界、尺寸、世界和所有者，确认选区没有偏移；
3. 让访客只能参观，或把可信玩家加入成员；
4. 用权限组给不同成员批量分配权限；
5. 通过环境 flag 控制生物、爆炸、火焰和其他世界行为；
6. 需要时设置传送点、进入/离开消息、地图颜色和子领地。

## 五分钟上手

### 1. 打开界面

在游戏内执行：

```text
/dominion
```

插件提供 ChestUI 和 Dialog 两种界面。第一次使用时，执行下面的命令选择界面：

```text
/dominion ui chest
/dominion ui dialog
/dominion ui default
```

`default` 会恢复服务端 `plugins/Dominion/config.yml` 中的 `ui.default`。如果 Dialog 不可用，插件会回退到 ChestUI。这不是权限失败。

### 2. 创建一个领地

最稳妥的流程是拿着选区工具，在同一个世界中分别左键和右键两个方块，然后执行：

```text
/dominion create home
```

如果只想保护当前位置附近的一小块区域，可以用自动创建：

```text
/dominion auto_create home
```

自动创建的半径由管理员配置的 `auto-create-radius` 决定；设为 `-1` 时该功能关闭。

### 3. 检查结果

站在领地内执行：

```text
/dominion info
```

它会显示领地名称、所有者、X/Y/Z 尺寸和高度范围。确认无误后，再进入[领地工作流](./claims)继续设置。

## Dominion 中的四种身份

| 身份 | 能力 | 权限来源 |
| --- | --- | --- |
| 访客 | 受领地 guest flag 约束；适合公开参观或默认拒绝操作 | 领地的访客权限 |
| 成员 | 被加入领地的玩家；可以拥有单独的成员 flag | 成员配置，或成员所属权限组 |
| 权限组成员 | 被加入某个组的成员；组 flag 会成为该成员的生效权限 | 权限组配置 |
| 领地主人/管理员 | 管理边界、成员、权限和领地设置 | 所有权、`admin` flag 或 `dominion.admin` |

成员加入时会以当时的访客权限作为初始基础；之后管理员改变访客权限，不会自动把已有成员的个人设置全部覆盖。一个成员加入权限组后，生效的是权限组的 flag，而不是成员页上单独保存的 flag，因此建议一个成员只选择一种主要管理方式。

## 推荐的使用顺序

1. 阅读[领地工作流](./claims)，先把边界和尺寸确定下来；
2. 阅读[成员与权限](./permissions)，只开放必要的操作；
3. 阅读[两种 UI](./ui)，了解 ChestUI 与 Dialog 的入口对应关系；
4. 需要查命令时使用[玩家命令参考](./commands)。

## 玩家侧的常见约定

- 领地名称在当前父级范围内必须唯一；子领地的名称可以与其他父领地下的名称重复。
- 选点必须在同一个世界；尺寸、最小高度和最大高度由管理员的限制文件决定。
- `/dominion info` 只能查询当前位置的领地；站在未认领区域时会返回“没有领地”。
- 传送可能有冷却或延迟；移动、取消或限制文件都可能让传送终止。
- 遇到“不能操作”时，先确认当前身份是访客、成员还是权限组成员，再检查对应 flag。不要只根据所在位置判断。

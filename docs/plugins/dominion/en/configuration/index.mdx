## File locations and order of changes

The main file is `plugins/Dominion/config.yml`. Claim flags, limits, and world-wide rules live in `flags.yml`, `limitations/`, and `world-wide/`; do not merge them into a legacy configuration layout.

Back up the database and configuration first. Then change database or multi-server settings before tuning claim limits and UI. Apply changes with `/dominion reload config` as an administrator or restart the server, and check the full log after bulk edits.

## Common settings

| Key | Default | Purpose |
| --- | --- | --- |
| `database.type` | `sqlite` | Choose `sqlite`, `mysql`, `mariadb`, or `pgsql`. The default database file is `plugins/Dominion/dominion.db`. |
| `multi-server.enable` | `false` | Enable multi-server mode through a shared database; SQLite is not supported in this mode. |
| `multi-server.server-name` | `server` | The server name corresponding to the proxy configuration. |
| `multi-server.server-id` | `1` | A unique positive integer in multi-server mode; do not change it after data exists. |
| `language` | `en_us` | Select a language file from `languages/`. |
| `ui.default` | `CHEST` | Default UI, either `CHEST` or `DIALOG`. |
| `auto-create-radius` | `10` | The radius used by `/dominion auto_create`; set `-1` to disable it. |
| `auto-clean-after-days` | `180` | Days before inactive player data is cleaned; set `-1` to disable it. |
| `server-spawn-protection-radius` | `10` | Radius around spawn where claims cannot be created. |
| `minimum-dominion-distance` | `0` | Minimum distance between claims. |
| `select-tool` / `info-tool` | `ARROW` / `STRING` | Items used for manual selection and click-to-inspect. |

## Messages and border display

`plugin-message` controls enter, leave, and no-permission notices. It supports `BOSS_BAR`, `ACTION_BAR`, `TITLE`, `SUBTITLE`, and `CHAT`; built-in placeholders include `{OWNER}` and `{DOM}`.

`border-display` controls the block border used while selecting or editing and the particles shown when crossing a claim boundary. Check performance on the target server before increasing particle density.

## Permission nodes

The current `plugin.yml` exposes two base nodes:

| Permission | Purpose |
| --- | --- |
| `dominion.default` | Regular Dominion commands, enabled by default for players |
| `dominion.admin` | Administrator commands and management UI, enabled by default for OPs |

Do not add `dominion.create` or `dominion.manage` based on older docs; the current commands use the base nodes above, while the owner, member flags, and limitation files decide the operation. Refresh your permissions plugin cache after changing access.

## Optional plugins

The `plugin.yml` file declares Vault, PlaceholderAPI, and WorldGuard as soft dependencies. They are not required for core claim protection. When installed, Dominion enables each integration if the plugin is available at startup.

### Vault: economy limitations

When you enable economy rules under `limitations/`, Dominion uses Vault to connect to an economy provider. It charges for claim creation or resizing according to the configured rules. Install Vault or a compatible implementation and an economy plugin. Do not enable balance-based limitations without a working economy service.

### PlaceholderAPI: message placeholders

With PlaceholderAPI installed, Dominion registers the `dominion` expansion. The expansion includes these placeholders:

```text
%dominion_current_dominion%
%dominion_group_title%
%dominion_is_member%
%dominion_members%
%dominion_member_count%
%dominion_group%
%dominion_groups%
%dominion_env_flag_<flag>%
%dominion_pri_flag_<flag>%
```

Selected-point coordinates, members of a named claim, and teleport coordinates have additional parameter forms. Use existing `<flag>` and claim names. Placeholders resolve only when PlaceholderAPI loads correctly.

### WorldGuard: claim conflict checks

When WorldGuard is enabled, Dominion registers the custom StateFlag `dominion-claim`. If a new or resized claim overlaps a WorldGuard region whose applicable `dominion-claim` state is `deny`, Dominion rejects the operation.

```text
/rg flag <region> dominion-claim deny
```

If WorldGuard already has an incompatible flag with that name, the startup log reports the conflict and Dominion disables its WorldGuard claim check. Resolve the conflict before testing claim creation.

## Database and multi-server mode

SQLite is the default, stored at `plugins/Dominion/dominion.db`. The available database types are:

- `sqlite`;
- `mysql`;
- `mariadb`;
- `pgsql`.

Multi-server mode is configured under `multi-server`:

```yaml
multi-server:
  enable: false
  server-name: server
  server-id: 1
```

Multi-server mode requires a shared database. SQLite is not supported. Do not change `server-id` after data exists. Give each server a unique positive integer. Stop the servers and back up the database before changing storage or enabling multi-server mode.

## Residence migration

Keep the `plugins/Residence` data before migrating, then enable this in `plugins/Dominion/config.yml`:

```yaml
residence-migration: true
```

A player can migrate one of their residences:

```text
/dominion migrate <residence_name>
```

An administrator can run `/dominion migrate_all`. Migration creates Dominion claims and attempts to preserve Residence subzones, teleport points, and enter/leave messages. Back up first. Inspect boundaries and permissions afterward.

## Database import and export

Administrators can use:

```text
/dominion export db
/dominion import db confirm
```

Use import for migration or backup restoration. Do not use it to merge databases. A non-empty target can fail and cause corruption or data loss. `export mca` creates an MCA list for claims. It is not a database backup.

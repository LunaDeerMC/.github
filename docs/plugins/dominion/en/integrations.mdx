## Optional plugins

The current `plugin.yml` declares Vault, PlaceholderAPI, and WorldGuard as soft dependencies. They are not required for core claim protection; when installed, Dominion enables each integration if the plugin is available at startup.

### Vault: economy limitations

When economy rules are enabled under `limitations/`, Dominion can use Vault to connect an economy provider and charge for claim creation or resizing according to the configured rules. Install both Vault (or a compatible implementation supported by the project) and an actual economy plugin. Do not enable balance-based limitations without a working economy service.

### PlaceholderAPI: message placeholders

With PlaceholderAPI installed, Dominion registers the `dominion` expansion. Examples from the current implementation include:

```text
%dominion_current_dominion%
%dominion_group_title%
%dominion_is_member%
%dominion_members%
%dominion_member_count%
%dominion_group%
%dominion_groups%
%dominion_env_flag_<flag>%
%dominion_pri_flag_<flag>%
```

Selected-point coordinates, members of a named claim, and teleport coordinates have additional parameter forms. Use values that exist on the current server for `<flag>` and claim names; placeholders resolve only when PlaceholderAPI is loaded correctly.

### WorldGuard: claim conflict checks

When WorldGuard is enabled, Dominion registers the custom StateFlag `dominion-claim`. If a new or resized claim overlaps a WorldGuard region whose applicable `dominion-claim` state is `deny`, Dominion rejects the operation.

```text
/rg flag <region> dominion-claim deny
```

If WorldGuard already has an incompatible flag with that name, the startup log reports the conflict and Dominion disables its WorldGuard claim check. Resolve the conflict before testing claim creation.

## Database and multi-server mode

SQLite is the default, stored at `plugins/Dominion/dominion.db`. The current database types are:

- `sqlite`;
- `mysql`;
- `mariadb`;
- `pgsql`.

Multi-server mode is configured under `multi-server`:

```yaml
multi-server:
  enable: false
  server-name: server
  server-id: 1
```

Multi-server mode requires a shared database; SQLite is not supported. Do not change `server-id` after data exists, and assign each server a unique positive integer. Stop the servers and back up the database before changing storage or enabling multi-server mode.

## Residence migration

Keep the `plugins/Residence` data before migrating, then enable this in `plugins/Dominion/config.yml`:

```yaml
residence-migration: true
```

A player can migrate one of their residences:

```text
/dominion migrate <residence_name>
```

An administrator can run `/dominion migrate_all`. Migration creates Dominion claims and attempts to preserve Residence subzones, teleport points, and enter/leave messages; back up first and inspect boundaries and permissions afterward.

## Database import and export

Administrators can use:

```text
/dominion export db
/dominion import db confirm
```

Import is for migration or backup restoration, not for merging two databases. A non-empty target can fail and cause corruption or data loss. `export mca` creates an MCA list related to claims; it is not a database backup.

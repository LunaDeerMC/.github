## Two permission layers

Dominion separates command access from actions inside a claim:

| Node | Default | Purpose |
| --- | --- | --- |
| `dominion.default` | All players | Regular Dominion commands. Ownership, member flags, and limitation files still limit each operation |
| `dominion.admin` | OP | Administrator commands such as reload, import/export, and bulk migration |

The `plugin.yml` file does not define separate `dominion.create` or `dominion.manage` nodes. Do not add those nodes to a permissions plugin. Check `plugin.yml` and `/dominion help` instead.

## Flags and managed objects

The generated `plugins/Dominion/flags.yml` is organized into two groups:

- `environment` for environmental behavior inside a claim;
- `privilege` for player interaction and management permissions.

Use the generated `flags.yml` and command completion for flag names. Do not paste an old flag list into a new configuration.

Dominion can manage:

- the owner, who manages the claim;
- guests, through claim-level default privilege flags;
- members, with per-player overrides;
- groups, which apply one set of flags to multiple members;
- privilege templates, which store flags for later use.

## Members and groups

A minimal member setup looks like this:

```text
/dominion member_add home Alice
/dominion member_set_pri home Alice <pri_flag_name> true
```

For a group:

```text
/dominion group_create home builders
/dominion group_add_member home builders Alice
/dominion group_set_flag home builders <pri_flag_name> true
```

Remove a member or group member with:

```text
/dominion member_remove home Alice
/dominion group_remove_member home builders Alice
```

Choose the flag for `member_set_pri` and `group_set_flag` from the server's completion list. Group membership affects the member's claim permissions. Verify the result with guest and world-wide rules.

## Templates and reuse

Templates belong to the player who creates them:

```text
/dominion template_create builder
/dominion template_set_flag builder <pri_flag_name> true
/dominion member_apply_template home Alice builder
/dominion template_rename builder builder_v2
/dominion template_delete builder_v2
```

To reuse settings between claims, copy environment flags, guest flags, members, or groups:

```text
/dominion copy_env source target
/dominion copy_guest source target
/dominion copy_member source target
/dominion copy_group source target
```

Confirm the target claim before copying. The command can change existing permissions. Players can run `/dominion title_use <title_id>` to use a group title. Pass `-1` to disable the group title.

## Permission troubleshooting

1. Confirm `dominion.default`. Confirm `dominion.admin` for administrator operations.
2. Test inside the target claim for member behavior. Test outside it for guest behavior.
3. Verify membership, group assignment, and flag names and values against `flags.yml`.
4. Check `limitations/` and `world-wide/` for a rule that rejects the operation.
5. Refresh the permissions plugin cache. Inspect the Dominion log after changes.

## 使用前提

TimeManager 的主命令是 `/ptime`。所有子命令都只能由玩家执行；从控制台执行时，插件会提示该命令只能由玩家使用。没有参数时，`/ptime` 会显示帮助信息。

## 命令总览

| 命令 | 所需权限 | 作用 |
| --- | --- | --- |
| `/ptime set <time>` | `ptime.set` | 设置自己的客户端时间。 |
| `/ptime reset` | 无额外节点 | 清除个人时间覆盖，完全恢复为服务器时间。 |
| `/ptime freeze` | `ptime.freeze` | 冻结当前个人时间。若此前没有覆盖，会从当前服务器时间开始冻结。 |
| `/ptime unfreeze` | `ptime.freeze` | 取消冻结，让个人时间继续按服务器节奏推进。 |
| `/ptime info` | 无额外节点 | 查看服务器时间、个人时间和同步/覆盖/冻结状态。 |
| `/ptime help` | 无额外节点 | 显示命令帮助和可用时间格式。 |

`reset`、`info` 和 `help` 没有单独的 TimeManager 权限节点，但服务器的命令权限管理器仍可能影响它们的可见性。权限不足时，插件会在游戏内返回错误提示。

## 时间格式

`/ptime set` 接受时间名称或 `0` 到 `24000`（含边界）的游戏刻：

| 输入 | 游戏刻 | 含义 |
| --- | ---: | --- |
| `sunrise` | `0` | 日出附近。 |
| `day` | `1000` | 早晨，通常作为白天起点。 |
| `noon` | `6000` | 正午。 |
| `sunset` | `12000` | 日落附近。 |
| `night` | `14000` | 夜晚。 |
| `midnight` | `18000` | 午夜。 |
| 数字 | `0–24000` | 直接使用指定的游戏刻。 |

名称不区分大小写。超过范围、使用负数或输入无法解析的文本时，插件会拒绝命令并提示正确格式。

## 常用流程

### 临时切换到白天

```text
/ptime set day
```

这只改变执行者看到的时间。拍摄完成后，可以用 `/ptime reset` 回到服务器的当前时间。

### 固定当前画面

```text
/ptime freeze
```

冻结后，个人时间不会继续变化。需要恢复推进时执行：

```text
/ptime unfreeze
```

如果希望完全清除个人覆盖状态，而不是只取消冻结，请使用 `/ptime reset`。

### 查看状态

```text
/ptime info
```

信息中会分别列出服务器时间和个人时间，并报告当前是 `SYNCHRONIZED`、`OVERRIDDEN` 还是 `FROZEN`。

## 权限配置

`plugin.yml` 中两个功能权限的默认值都是 `true`：

| 权限节点 | 默认值 | 控制内容 |
| --- | --- | --- |
| `ptime.set` | `true` | `/ptime set`。 |
| `ptime.freeze` | `true` | `/ptime freeze` 与 `/ptime unfreeze`。 |

如果服务器希望只允许摄影组或管理组使用个人时间，可以在权限插件中先关闭普通组继承，再按需授予上述两个节点。修改权限后，用没有 OP 的测试账号验证；OP 账号可能绕过权限插件的普通组规则。

TimeManager 不提供让管理员替其他玩家设置时间的命令，`/ptime` 的执行者始终是当前玩家。需要查看问题时，请同时记录玩家是否拥有节点、具体命令、服务端核心版本和控制台日志。

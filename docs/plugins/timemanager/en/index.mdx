## Who this documentation is for

These pages serve server owners and administrators who need to deploy the plugin, as well as ordinary players who only want to adjust their own view. TimeManager has a focused feature set, so the documentation stays at two pages: this page covers installation, first start, and configuration; the next page covers commands, time formats, and permissions.

## What TimeManager changes

TimeManager sets client-side time for the player who uses it without changing the server world time. Other players continue to follow the server day-night cycle, and crops, mobs, redstone, weather, and scheduled events are not changed by one player's command.

This makes it useful for photographing builds, checking a scene under different lighting, or freezing a personal view without affecting the server. It is not a server-wide time controller and does not permanently set the world to day or night.

## Compatibility and requirements

- Minecraft API: `1.21`.
- Java: `21`.
- Servers: Paper, Spigot, and Folia.
- Plugin type: Bukkit/Paper plugin installed in the server's `plugins/` directory.

If your server, Java runtime, or plugin version differs from this range, validate it on a test server first. On Folia, check that the rest of the installed plugins are Folia-compatible as well; TimeManager declares Folia support in `plugin.yml`.

## Installation and first start

1. Stop the server and back up the worlds, `plugins/`, and server logs.
2. Get a JAR suitable for the current version from the [TimeManager GitHub repository](https://github.com/LunaDeerMC/TimeManager). If the repository has no pre-built file, run `mvn clean package` with Java 21 according to the project's Maven configuration, then choose the build artifact from `target/`.
3. Put the JAR in the server's `plugins/` directory. Do not keep multiple TimeManager versions there.
4. Start the server and check the console for a successful plugin enable message.
5. On first enable, the plugin generates `plugins/TimeManager/config.yml`. Restart the server after editing it; the current project does not provide a configuration reload command.
6. Use a normal player account to run `/ptime info` and `/ptime set day`. Confirm that only that account's view changes, then use `/ptime reset` to clean up the test.

If the plugin does not load, start with Java, API, and dependency errors in the server log; do not infer compatibility from the JAR filename alone.

## Configuration

TimeManager creates its configuration from the source configuration class on first start. The default fields are:

| Key | Default | Purpose |
| --- | --- | --- |
| `debug` | `false` | Enable debug logging. |
| `enable-time-command` | `true` | Register the `/ptime` command. When disabled, the plugin does not register its command executor. |
| `show-welcome-message` | `true` | Try to show a welcome message when a player joins. |
| `welcome-message` | `&aTimeManager is enabled! Use &e/ptime help &afor commands.` | Join message; Bukkit `&` color codes are supported. |

The current repository's join listener checks the `timeessence.use` permission, while `plugin.yml` declares only `ptime.set` and `ptime.freeze`. As a result, the welcome message may not appear even when `show-welcome-message` is `true`. Do not use that message as the health check; prefer the server log and an actual command.
